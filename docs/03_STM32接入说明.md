# STM32/C30D 接入说明

## 1. 基准工程

本项目按用户资料中的以下版本核对接口：

```text
3.STM32运动底盘源码/
当前版本代码（适配STM32控制板_D版_2022.05.17-现在）/
C30D-2.0版/
R550_C30D(2.0)_Mini小车STM32源码_GMR编码器_2025.12.26
```

已核对的原接口：

- `Read_Encoder(2/3)` 读取 TIM2/TIM3 并清零；
- `Set_Pwm(a,b,c,d,servo)` 输出四路 PWM 和舵机；
- `CAN1_Rx_Msg` 会保留完整 CAN ID；
- `CAN1_Tx_Msg` 发送标准帧；
- `Voltage` 单位是 V；
- `EN` 为硬件使能输入；
- `Write_Flash` 每次先擦除参数扇区，`Read_Flash(index)` 按 word 读取；
- CAN1 参数对应 1 Mbit/s。

把新目录以及原有 `BALANCE`、`HARDWARE`、FreeRTOS include 路径加入 C/C++ Include Paths。确保编译器启用硬件单精度浮点；STM32F407 有 FPU。

## 3. 关闭原 CAN RX0 中断

本项目用 2 ms CAN 任务读取 FIFO，从而在普通任务上下文中统一处理多个 ID。修改原 `HARDWARE/can.h`：

```c
#define CAN1_RX0_INT_ENABLE 0
```

这样原 `CAN1_RX0_IRQHandler` 不会先把 `0x101` 从 FIFO 取走。CAN 初始化和过滤器仍保留不变。

## 4. 替换唯一电机控制任务

在 `USER/main.c` 顶部加入：

```c
#include "chassis_tasks.h"
```

在 `start_task` 内删除或注释原来的：

```c
xTaskCreate(Balance_task, ...);
```

改为：

```c
if (!chassis_tasks_start())
{
    Set_Pwm(0, 0, 0, 0, 0);
}
```

完整参考见 `firmware/stm32f407/integration/main_start_task_example.c`。

### 为什么必须停用 `Balance_task`

原任务和新任务都会：

- 调用 `Read_Encoder`，而该函数读取后会把计数器清零；
- 计算电机目标；
- 调用 `Set_Pwm` 写同一组寄存器。

两个任务并存会造成轮流清零编码器、PWM 相互覆盖，表现为速度乱跳甚至突然转动。这不是优先级能彻底解决的问题，必须保证只有一个执行者。

原 `data_task` 会使用旧的 `MOTOR_A.Encoder` 等数据，建议首轮也不创建；确认不冲突后再决定是否保留串口/OLED功能。IMU、OLED、LED 任务本身可以保留，但若 OLED 依赖旧全局量，其显示不会代表新控制器。

## 5. Flash 参数占用

本项目复用 `FLASH_SAVE_ADDR` 并写入完整 `chassis_params_t`，因此会覆盖原工程曾保存的 `RC_Velocity`、`Velocity_KP`、`Velocity_KI` 和 `LineDiffParam`。因为原 `Balance_task` 已停用，这些旧参数不再参与控制。

如果同一份固件还要保留原控制模式，必须在 `stmflash.h` 中另划一个独立扇区地址，并分别做扇区边界、容量和擦写寿命检查，不能共享 `FLASH_SAVE_ADDR`。

### 链接区必须避开参数扇区

原资料的 `WHEELTEC.sct` 把 IROM 大小写成了 1 MiB，但 STM32F407VE 是 512 KiB，参数地址又是 `0x08060000`。项目提供 `integration/WHEELTEC_reserve_sector7.sct`，将应用程序限制在前 384 KiB，把 sector 7 完整留给参数。建议在 Keil Linker 页面选择该文件。每次构建后确认 map 中 `ER_IROM1 Max` 为 `0x00060000`，而不是 `0x00100000`。

## 6. 四个必须核对的配置

打开 `c30d_chassis_port.h`：

```c
#define C30D_LEFT_ENCODER_TIMER  2U
#define C30D_RIGHT_ENCODER_TIMER 3U
#define C30D_LEFT_ENCODER_SIGN   1
#define C30D_RIGHT_ENCODER_SIGN  (-1)
#define C30D_LEFT_PWM_SIGN       1
#define C30D_RIGHT_PWM_SIGN      1
```

资料中的 R550/差速/阿克曼逻辑使用 TIM2 为 A、TIM3 为 B，且 B 编码器取反，因此给出上述默认值。实车必须验证：

1. 单独给左轮很小的正 PWM，确认左轮向前。
2. 单独给右轮很小的正 PWM，确认右轮向前。
3. 手动让左轮向前转，确认 `0x183` 增量为正。
4. 手动让右轮向前转，确认 `0x184` 增量为正。

若电机方向错，只改对应 `PWM_SIGN`；若计数方向错，只改 `ENCODER_SIGN`。不要在 PI 或运动学中临时加负号。

## 7. 车体类型

- 两轮差速、四轮差速但左右各并作一组：`chassis_type = 0`。
- R550 阿克曼：`chassis_type = 1`，还要标定舵机中值、每弧度 PWM 和上下限。

本接口当前把 A/B 当作两个驱动轮，C/D 输出为零，适合 R550 两驱配置。如果实车是 V550 四驱或麦克纳姆，不能简单把 C/D 复制 A/B；应增加四轮控制器和对应运动学，这是一个明确的后续扩展点。

## 8. 编译与烧录前检查

- 无重复定义 `CAN1_RX0_IRQHandler`。
- 无原 `Balance_task` 创建语句。
- `CHASSIS_CONTROL_TASK_PRIO` 高于普通显示和通信任务。
- heap 足以创建两个 512-word 栈和 mutex。
- 资料工程的 `configUSE_MUTEXES=1`、heap=20 KiB 已满足默认设置；仍建议把 `configCHECK_FOR_STACK_OVERFLOW` 从 0 改为 2，并实现栈溢出钩子做实机压力验证。
- `sizeof(chassis_params_t)` 为 4 的整数倍，且参数扇区容量足够。
- 编译无 implicit declaration、指针截断和 float/double 告警。
- 烧录后先保持 `EN=0`，检查 0x700 心跳和 0x185 状态。
