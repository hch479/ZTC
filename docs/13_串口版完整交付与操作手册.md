# C30D 电机闭环 + RDK X5 ROS 2 串口版完整交付与操作手册

## 0. 先直接回答你的两个问题

### 0.1 下位机程序到底烧进去了吗？

已经烧进去了，而且有三层验证，不是只在电脑上生成了一个 HEX 文件：

1. Keil 使用 ARM Compiler 5.06 完整编译，结果为 `0 Error(s), 0 Warning(s)`；
2. ST-Link/pyOCD 识别到实际芯片为 `STM32F407VETx`，按扇区写入串口版固件；
3. 写入后停止 CPU 回读 Flash，将 HEX 的 73,768 个有效地址逐字节比较，错误数为 0。

参数区 `0x08060000..0x0807FFFF` 在烧录前后 SHA-256 都是：

```text
B5A41C3758763BBEC72769FAB4A2533BF2DB0B6312D93D25A695F9E4B9E02260
```

所以参数区没有被这次烧录擦掉。随后 RDK X5 实际收到了新协议的 `A5 5A` 串口帧，
ROS 诊断显示 `IDLE / NONE`，这也证明板上运行的是新串口程序。

### 0.2 ROS 程序原来放在哪里？

上一轮是直接部署到真正的 RDK X5 板子上：

```text
/home/wheeltec/chassis_project/ros2_ws
```

不是放在 VMware 的 Ubuntu 虚拟机里，所以你之前在虚拟机里看不到是正常的。

现在交付包中已经提供同一份 ROS 2 源码，并另外复制到了虚拟机桌面。需要注意：

- 虚拟机中的副本主要用于阅读、修改和离线编译；
- 真正控制小车时，ROS 节点应运行在 RDK X5，因为小车 USB 串口实际接在 RDK X5 上；
- 在虚拟机中启动节点，除非把 USB 底盘串口从 RDK 拔下并转接给虚拟机，否则会找不到设备。

## 1. 当前系统由什么组成

```text
ROS 2 /cmd_vel
       ↓
RDK X5 串口 ROS 节点
       ↓ 115200, 8N1, USB 串口序列号 0002
STM32 USART3 串口协议解析
       ↓
运动学 + 速度斜坡 + 前馈/PI 闭环 + 安全保护
       ↓
PWM → AT8236 功率驱动 → 电机
       ↑
AB 相编码器测速和累计计数
```

AT8236 在这里主要负责功率放大。编码器读取、轮速计算、闭环计算和 PWM 输出均由
STM32F407 完成。

## 2. 下位机现在具有的功能

### 2.1 串口通信

- USART3，115200 baud、8 data bits、no parity、1 stop bit；
- 双字节帧头 `A5 5A`；
- 固定 15 字节帧；
- 包含协议版本、逻辑消息 ID、8 字节数据和 CRC-8/ATM；
- 能从错位、噪声或坏 CRC 中重新寻找帧头；
- 接收中断只负责组帧，复杂处理放在 FreeRTOS 任务中。

### 2.2 电机控制

- 读取左右电机 AB 相编码器；
- 根据编码器增量计算实际轮速；
- 阿克曼或差速运动学，将车体线速度/角速度转换为左右轮目标速度；
- 目标速度加减速斜坡，避免突然启动和突然反转；
- 编码器速度一阶低通滤波；
- 每个车轮独立执行“前馈 + PI”速度闭环；
- 正反转死区补偿；
- 条件积分抗饱和；
- 直行时左右轮同步补偿；
- 输出 PWM 给厂家已经验证过的 `Set_Pwm()` 硬件函数。

### 2.3 安全保护

- 上电默认软件失能；
- ROS 必须显式调用 `/chassis/enable` 才允许输出；
- 200 ms 没收到有效命令时自动停车；
- 急停命令锁存；
- 欠压检测；
- 编码器数据异常检测；
- 电机堵转检测；
- 参数范围和 CRC 校验；
- 任务或互斥锁异常时输出零；
- 蜂鸣器 PA8 始终输出低电平，所有开启入口已关闭。

### 2.4 数据反馈

STM32 周期上传：

- 左右轮目标速度和实际速度；
- 左右电机 PWM 和速度误差；
- 左右编码器累计值和单周期增量；
- 控制状态、故障位和电池电压；
- STM32 运行时间和固件版本心跳；
- 参数读写结果。

RDK 将这些数据转换为：

- `/odom`；
- `/joint_states`；
- `/motor/debug`；
- `/diagnostics`；
- TF：`odom -> base_link`。

## 3. 为什么 Keil 工程里还有很多以前的代码

因为这不是一块空白 STM32 开发板。新控制代码仍然要依靠厂家已经验证过的板级代码。
如果只留下十几个新文件，工程将缺少启动文件、芯片库、操作系统和实际引脚驱动，无法编译，
也无法控制这块 C30D 板。

### 3.1 必须保留并且仍在使用的厂家代码

| 目录 | 作用 |
|---|---|
| `CORE` | STM32F407 启动文件和 Cortex-M4 定义 |
| `FWLIB` | STM32F4 标准外设库 |
| `FreeRTOS` | 任务调度、延时、互斥锁 |
| `HARDWARE/encoder.*` | AB 相编码器计数 |
| `HARDWARE/motor.*`、`timer.*` | PWM 和电机方向输出 |
| `HARDWARE/usartx.*` | USART3 引脚、波特率和发送函数 |
| `HARDWARE/adc.*` | 电池电压采样 |
| `HARDWARE/stmflash.*` | 参数保存到内部 Flash |
| `BALANCE/system.*` | 整块 C30D 板硬件初始化 |
| `USER`、`SYSTEM` | main、系统时钟、中断和延时 |

### 3.2 文件保留但当前正常模式没有运行的旧功能

- 原 `Balance_task` 没有被创建；
- 原手柄任务没有被创建；
- 原 `data_task` 没有被创建；
- 原 ROS 11 字节串口控制解析被 `#if 0` 排除；
- 旧 CAN 控制不会参与串口版的运动命令处理。

保留这些源文件的目的，是避免粗暴删除厂家代码导致板级初始化或其他引用关系损坏，同时也方便
以后对照和恢复。判断一个旧模块是否真的在运行，不能只看文件是否存在，要看 `USER/main.c`
是否创建了对应任务。当前正常模式只调用 `chassis_tasks_start()` 创建新控制任务和新串口任务。

## 4. 你真正应该阅读的下位机文件

按下面顺序阅读，不要从 `FWLIB` 开始：

1. `USER/main.c`：程序入口，能看到新任务取代旧电机任务；
2. `CHASSIS_SERIAL/inc/chassis_serial_transport.h`：15 字节串口帧格式；
3. `CHASSIS_SERIAL/src/chassis_serial_transport.c`：串口组帧、CRC、收发队列；
4. `CHASSIS_SERIAL/src/chassis_tasks.c`：10 ms 控制任务和遥测任务；
5. `CHASSIS_SERIAL/src/chassis_app.c`：运动学、状态机和安全保护；
6. `CHASSIS_SERIAL/src/wheel_controller.c`：前馈 + PI、斜坡、滤波和抗饱和；
7. `CHASSIS_SERIAL/src/chassis_params.c`：默认参数、范围和 CRC32；
8. `CHASSIS_SERIAL/src/c30d_chassis_port.c`：新算法与厂家编码器/PWM/Flash 函数的连接处；
9. `CHASSIS_SERIAL/src/chassis_can_protocol.c`：名字保留了 `can`，但这里其实是串口和 CAN
   共用的“逻辑消息编码”，并不代表串口版正在使用 CAN 物理接口。

## 5. 你真正应该阅读的 ROS 文件

1. `chassis_can_control/chassis_can_node.py`：ROS 话题、服务、参数和诊断主节点；
2. `chassis_can_control/serial_transport.py`：Linux 串口打开、15 字节包收发；
3. `chassis_can_control/can_protocol.py`：与 STM32 一致的逻辑消息编码；
4. `chassis_can_control/wheel_odometry.py`：编码器里程计；
5. `config/chassis_serial.yaml`：串口路径、PI、车体尺寸和安全阈值；
6. `launch/chassis_serial.launch.py`：串口版启动入口；
7. `scripts/start_chassis_serial_safe.sh`：安全启动；
8. `scripts/stop_chassis_serial_safe.sh`：软件失能并停止节点。

## 6. Windows 上打开和编译下位机

### 6.1 打开

进入：

```text
02_下位机串口版_Keil完整工程\USER\WHEELTEC.uvprojx
```

双击该文件，或双击工程根目录的 `OPEN_KEIL_PROJECT.bat`。

### 6.2 编译

在 Keil 中点击 `Project -> Rebuild all target files`，或者运行：

```text
BUILD_WITH_KEIL.bat
```

必须看到：

```text
0 Error(s), 0 Warning(s)
```

输出文件：

```text
OBJ_SERIAL\C30D_SERIAL_MOTOR.hex
```

### 6.3 烧录

烧录前：

1. 车轮架空并固定；
2. 关闭电机硬件使能，最好断开电机主电源；
3. ST-Link 接 GND、SWDIO、SWCLK，推荐连接 NRST；
4. 确认 Device 是 `STM32F407VE`；
5. 确认 Flash 算法是 `STM32F4xx 512KB Flash`；
6. 选择 `Erase Sectors`，不要选择 `Erase Full Chip`；
7. 勾选 Program、Verify、Reset and Run；
8. 点击 Keil 的 Download。

本项目链接区域固定为 `0x08000000..0x0805FFFF`，参数区从 `0x08060000` 开始。

## 7. RDK X5 上操作 ROS 2

### 7.1 登录 RDK

在虚拟机终端中：

```bash
ssh wheeltec@192.168.0.100
```

### 7.2 程序位置

```bash
cd ~/chassis_project/ros2_ws
```

### 7.3 重新编译

```bash
source /opt/ros/humble/setup.bash
colcon build --packages-select chassis_can_control
source install/setup.bash
```

### 7.4 确认底盘串口

```bash
ls -l /dev/serial/by-id/
```

本车已确认：

```text
0002 = 底盘控制器
0001 = 雷达
```

配置使用的完整路径是：

```text
/dev/serial/by-id/usb-WCH.CN_USB_Single_Serial_0002-if00
```

不要直接写死 `/dev/ttyACM0`，因为重启后编号可能交换。

### 7.5 安全启动

```bash
bash src/chassis_can_control/scripts/start_chassis_serial_safe.sh
```

该脚本只启动节点，不会自动使能电机。

如果旧版脚本曾出现：

```text
/opt/ros/humble/setup.bash: line 8: AMENT_TRACE_SETUP_FILES: unbound variable
```

原因是 Bash 在加载 ROS 环境前执行了 `set -u`。当前脚本已经修正为先 `source` ROS 环境，
再开启未定义变量检查。该错误与 STM32、串口和电机无关。

### 7.6 查看状态

另开一个终端登录 RDK：

```bash
source /opt/ros/humble/setup.bash
source ~/chassis_project/ros2_ws/install/setup.bash
ros2 topic echo /diagnostics
```

正常应看到：

```text
message: IDLE
faults: NONE
transport: serial
heartbeat_age: 小于 2 秒
```

查看电机目标、实测速度、PWM 和误差：

```bash
ros2 topic echo /motor/debug
```

### 7.7 第一次低速测试

必须先把车轮架空。然后：

```bash
ros2 service call /chassis/enable std_srvs/srv/SetBool "{data: true}"
```

持续发送很小的前进速度：

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.05}, angular: {z: 0.0}}"
```

按 `Ctrl+C` 停止速度发送，再执行：

```bash
ros2 service call /chassis/enable std_srvs/srv/SetBool "{data: false}"
```

### 7.8 一键停止

```bash
bash ~/chassis_project/ros2_ws/src/chassis_can_control/scripts/stop_chassis_serial_safe.sh
```

## 8. ROS 参数在哪里修改

修改 RDK 上的：

```text
~/chassis_project/ros2_ws/src/chassis_can_control/config/chassis_serial.yaml
```

其中：

- `controller.left_kp/right_kp`：比例项；
- `controller.left_ki/right_ki`：积分项；
- `controller.left_kff/right_kff`：速度前馈；
- `dead_forward/dead_reverse`：正反转死区；
- `geometry.*`：轮径、轮距、轴距、编码器计数；
- `limits.*`：最高速度和加减速度；
- `safety.*`：超时、欠压和堵转保护。

修改后重新启动节点。不要在车轮落地或电机运行时大幅修改参数，也不要第一次就执行
`push_parameters` 和保存 Flash。

## 9. 恢复原厂固件

原厂 512 KiB 完整备份位于交付包：

```text
05_原厂固件备份与烧录证据\C30D_factory_full_read1.bin
```

恢复前再次备份当前固件。原厂 BIN 的起始地址是：

```text
0x08000000
```

恢复整片原厂固件属于主动回退操作，才会使用整片擦除。普通更新本项目固件始终使用扇区擦除。

## 10. CAN 版本在哪里

CAN 完整工程仍保留在交付包的：

