## 当前物理层结论

RDK can0 在 1 Mbit/s 下发送零速度且软件失能的测试帧后进入 ERROR-PASSIVE；
STM32 CAN 错误寄存器显示 TEC=128 和 ACK Error。两端均已正确初始化为
1 Mbit/s，但双方没有收到对方的应答。

因此剩余阻塞在物理总线：检查 RDK CAN 插座到 C30D 的 GND、CAN_L、CAN_H，
检查 C30D 供电，并确保总线两端各有一个 120 欧姆终端电阻。首次通车前保持
硬件电机使能关闭并架空车轮。

## RDK 安全命令

```bash
cd ~/chassis_project/ros2_ws

# 只监听，不发控制命令
bash src/chassis_can_control/scripts/diagnose_can_safe.sh

# 启动 ROS 节点，但软件电机使能仍为 OFF
bash src/chassis_can_control/scripts/start_chassis_safe.sh

# 请求软件失能并关闭 can0
bash src/chassis_can_control/scripts/stop_chassis_safe.sh
```

在 `diagnose_can_safe.sh` 中看到周期性的 `700`、`185` 等帧后，才能继续做
软件 enable 和低速车轮测试。
