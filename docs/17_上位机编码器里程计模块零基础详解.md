# RDK X5 上位机编码器里程计模块零基础详解

## 1. 这份文档讲什么

本文只讲 RDK X5 上位机的第 5 个模块：编码器里程计模块。

主要涉及：

```text
wheel_odometry.py
chassis_can_node.py
can_protocol.py 中的 EncoderData 和 decode_encoder()
```

它和你已经大致理解的前四个模块这样连接：

```text
STM32 编码器遥测
    ↓

    ↓
协议模块解码
    ↓
主节点配对左右编码器
    ↓
WheelOdometry 计算位姿
    ↓
主节点发布 /odom、/joint_states 和 TF
```

本文会从最基础的问题开始：

- 编码器到底提供什么？

- Python 的类、对象、 `self`、`Optional` 是什么意思？
- ROS 2 的 `/odom`、`/joint_states` 和 TF 各有什么作用？

- 当前里程计有没有使用 IMU？

## 2. 先用一句话理解编码器里程计

编码器里程计就是：

```text
根据左右车轮转过多少圈，估算小车走了多远、转了多少角度，
再把每一小段运动不断累加，得到当前 x、y 和朝向 yaw。
```

这里有两个关键词。

第一是“估算”。编码器不是绝对位置传感器，轮胎打滑时会产生误差。

第二是“累加”。每一小段都有一点误差，运行时间越长，累计误差通常越大。

## 3. 整个数据链

当前实车的完整链路是：

```text
左右车轮转动
    ↓
编码器产生 A/B 相脉冲
    ↓
STM32 定时器统计脉冲
    ↓
STM32 每 10 ms 读取增量并累加 total_count
    ↓
STM32 每 50 ms 上传一对左右累计计数
    ↓ USART3，15 字节串口帧
RDK serial_transport.py 收到完整帧
    ↓
can_protocol.py 解码成 EncoderData
    ↓
chassis_can_node.py 按 sequence 配对左右数据
    ↓
wheel_odometry.py 计算 x、y、yaw 和车轮角度
    ↓
chassis_can_node.py 发布
    ├─ /odom
    ├─ /joint_states
    └─ TF：odom → base_link
```

`wheel_odometry.py` 不打开串口，也不直接使用 ROS。它只解决一个数学问题：

```text
输入：左右累计编码器计数和几何参数
输出：小车位置、朝向和左右轮累计角度
```

这样拆分后，数学模块可以脱离 ROS 和硬件单独测试。

## 4. 编码器最基础的概念

### 4.1 编码器输出的不是米

编码器输出的是脉冲计数。车轮正转时计数增加，反转时计数减少：

```text
0 → 20 → 43 → 65 → 89
0 → -18 → -39 → -62
```

编码器不知道轮径、轮距，也不知道小车在地图中的位置。软件必须结合机械参数换算。

### 4.2 增量计数和累计计数

STM32 保存两种计数：

```text
delta_count：这一控制周期增加或减少了多少
total_count：从复位以来累计了多少
```

例如：

```text
第 1 次：delta=100，total=100
第 2 次：delta=120，total=220
第 3 次：delta=110，total=330
```

RDK 里程计主要使用 `total_count`，用当前累计值减去上次累计值，得到两批遥测之间的变化。

它比只依赖单次 `delta_count` 更能抵抗偶发的遥测丢帧。即使中间一批没有传到 RDK，下一批累计值仍然包含中间走过的计数。

### 4.3 当前几何参数

`config/chassis_serial.yaml` 中：

```yaml
geometry.wheel_diameter_m: 0.065
geometry.wheel_track_m: 0.162
geometry.counts_per_wheel_rev: 60000.0
```

含义：

```text
wheel_diameter_m       轮径 0.065 m，也就是 65 mm
wheel_track_m          左右轮中心横向距离 0.162 m
counts_per_wheel_rev   车轮轴转一圈对应 60000 个计数
```

`counts_per_wheel_rev` 必须是车轮最终转一圈的计数。如果编码器安装在电机轴上，要把减速比和 A/B 相倍频计入。

## 5. 从计数换算成距离

### 5.1 车轮一圈走多远

```text
车轮周长 = π × 轮径
```

当前：

```text
π × 0.065 ≈ 0.204204 m
```

理想无打滑时，车轮转一圈对应约 0.204 m。

### 5.2 一个计数对应多少米

```text
每计数距离 = π × 轮径 / 每圈计数
           = π × 0.065 / 60000
           ≈ 0.00000340339 m
```

即：

```text
1 个计数 ≈ 3.403 微米
```

代码：

```python
meters_per_count = math.pi * wheel_diameter_m / counts_per_wheel_rev
```

其中 `math.pi` 是 π，`*` 是乘法，`/` 是除法。

### 5.3 左右轮距离

```python
left_distance = left_delta * meters_per_count
right_distance = right_delta * meters_per_count
```

若左轮增加 1000 个计数：

```text
左轮距离 ≈ 1000 × 0.00000340339
         ≈ 0.003403 m
         ≈ 3.403 mm
```

## 6. 左右轮距离怎样决定车体运动

### 6.1 左右相等：直行

```text
左轮距离 = 0.10 m
右轮距离 = 0.10 m
```

小车中心前进 0.10 m，朝向不变。

### 6.2 右轮更远：向左转

```text
左轮距离 = 0.08 m
右轮距离 = 0.12 m
```

右侧走得更远，小车向左转。可以想象两个人并排前进，右边的人走得更快，队伍会向左绕。

### 6.3 中心距离

代码：

```python
center_distance = 0.5 * (left_distance + right_distance)
```

即：

```text
中心距离 = (左轮距离 + 右轮距离) / 2
```

### 6.4 朝向变化

代码：

```python
yaw_delta = (right_distance - left_distance) / wheel_track_m
```

即：

```text
朝向变化 = (右轮距离 - 左轮距离) / 左右轮距
```

单位是弧度 rad。左右距离相等时，差为 0，所以不转向。右轮更远时 `yaw_delta` 为正，按 ROS 坐标约定表示向左转。

## 7. ROS 坐标系中的 x、y、yaw

地面机器人常用右手坐标系：

```text
x 轴：小车正前方
y 轴：小车左侧
z 轴：小车上方
```

二维里程计主要关心：

```text
x    在 odom 坐标系前后方向的位置，m
y    在 odom 坐标系左右方向的位置，m
yaw  绕 z 轴的朝向，rad
```

初始时：

```text
x=0，y=0，yaw=0
```

这只是把节点启动时的位置作为局部里程计原点，不代表地图的绝对原点。

常见弧度换算：

```text
π rad   = 180°
π/2 rad = 90°
0.1 rad ≈ 5.73°
```

## 8. 怎样累加 x 和 y

若小车始终朝 x 正方向，中心移动距离全部加到 x。但小车转向后，要把距离分解：

```text
Δx = 中心距离 × cos(朝向)
Δy = 中心距离 × sin(朝向)
```

当前代码使用本次小运动的中点方向：

```python
middle_yaw = self.yaw_rad + 0.5 * yaw_delta
self.x_m += center_distance * math.cos(middle_yaw)
self.y_m += center_distance * math.sin(middle_yaw)
```

`+=` 表示在原值上累加：

```python
self.x_m += value
```

等价于：

```python
self.x_m = self.x_m + value
```

为什么用中点方向？因为这 50 ms 内小车可能一边走一边转。用“起始方向 + 本次转角的一半”近似整段轨迹，通常比只用起点方向误差小。

## 9. 为什么 yaw 要限制到 -π 到 π

一直旋转时角度会不断增加。方向转一整圈后其实重复，因此代码：

```python
self.yaw_rad = math.atan2(
    math.sin(self.yaw_rad + yaw_delta),
    math.cos(self.yaw_rad + yaw_delta),
)
```

将等价角度规范到约 `[-π, π]`：

```text
190° 等价于 -170°
370° 等价于 10°
```

这不改变朝向，只改变表示方式。

## 10. `wheel_odometry.py` 中的 Python 基础

### 10.1 导入

```python
from dataclasses import dataclass
import math
from typing import Optional
```

- `dataclass`：方便定义只保存数据的类；
- `math`：提供 π、正弦、余弦和反正切；
- `Optional`：表示变量可能有一个值，也可能暂时是 `None`。

### 10.2 结果数据类

```python
@dataclass
class OdometrySample:
    x_m: float
    y_m: float
    yaw_rad: float
    left_wheel_angle_rad: float
    right_wheel_angle_rad: float
```

它像一张“本次里程计结果表”。访问时使用名字：

```python
sample.x_m
sample.yaw_rad
```

比返回一个不知道每个下标含义的列表更清楚。

### 10.3 `WheelOdometry` 类

```python
class WheelOdometry:
```

里程计必须记住上次计数和已经累计的 x、y、yaw，因此适合做成对象。

主节点创建一个实例：

```python
self._odometry = WheelOdometry()
```

之后每一批数据都调用同一个对象，它会保留历史状态。

### 10.4 `self`

`self` 表示当前对象本身。`self.x_m` 是当前这个里程计对象自己的 x。

如果创建两个对象：

```python
odom_a = WheelOdometry()
odom_b = WheelOdometry()
```

它们的 x、y、上次计数互不影响。

### 10.5 构造函数

```python
def __init__(self) -> None:
    self.reset()
```

创建 `WheelOdometry()` 时自动执行，将状态初始化。

### 10.6 `reset()`

```python
def reset(self) -> None:
    self.x_m = 0.0
    self.y_m = 0.0
    self.yaw_rad = 0.0
    self.left_wheel_angle_rad = 0.0
    self.right_wheel_angle_rad = 0.0
    self._previous_left_count = None
    self._previous_right_count = None
```

位置和角度归零。上次计数设为 `None`，表示还没建立第一次基准。

### 10.7 `Optional[int]`

```python
self._previous_left_count: Optional[int] = None
```

它可能是：

```text
None       尚未收到第一批编码器数据
某个 int   已保存上一批累计计数
```

### 10.8 静态方法

```python
@staticmethod
def wrapped_count_delta(current: int, previous: int) -> int:
```

这个函数只依赖传入的两个计数，不需要 x、y 等对象状态，因此是静态方法。

## 11. 为什么第一批计数只建立基准

代码：

```python
if self._previous_left_count is None or self._previous_right_count is None:
    self._previous_left_count = left_count
    self._previous_right_count = right_count
    return self.sample()
```

假设 STM32 已运行一段时间，累计值为：

```text
左轮 120000
右轮 119500
```

这时才启动 RDK 节点。如果直接把它们当成节点启动后的运动，`/odom` 会瞬间跳动。

所以第一批只记录“我开始观察时的基准”。返回的 x、y、yaw 仍为零，下一批才和这个基准比较。

## 12. 32 位累计计数为什么会环绕

STM32 使用 32 位有符号累计计数：

```text
最小值 -2147483648
最大值  2147483647
```

最大值再加 1 会绕到最小值：

```text
2147483647 → -2147483648
```

真实变化只是 +1，但普通相减会得到一个巨大负数。代码：

```python
return ((current - previous + (1 << 31)) % (1 << 32)) - (1 << 31)
```

将差值按 32 位圆环重新映射，所以：

```text
current=-2147483648
previous=2147483647
正确 delta=1
```

其中：

```text
1 << 31  表示 2³¹
1 << 32  表示 2³²
%        取模，超过范围后绕回
```

## 13. `update()` 逐段理解

函数输入：

```python
def update(
    self,
    left_count: int,
    right_count: int,
    wheel_diameter_m: float,
    counts_per_wheel_rev: float,
    wheel_track_m: float,
) -> Optional[OdometrySample]:
```

输入是左右累计计数、轮径、每圈计数和轮距。成功返回 `OdometrySample`；参数非法时返回 `None`。

### 13.1 参数检查

```python
if (
    wheel_diameter_m <= 0.0
    or counts_per_wheel_rev <= 0.0
    or wheel_track_m <= 0.0
):
    return None
```

三个几何参数都必须大于零。`or` 表示只要其中一个条件成立就拒绝计算。

### 13.2 计算本批变化

```python
left_delta = self.wrapped_count_delta(
    left_count, self._previous_left_count
)
right_delta = self.wrapped_count_delta(
    right_count, self._previous_right_count
)
```

随后更新“上一次”：

```python
self._previous_left_count = left_count
self._previous_right_count = right_count
```

### 13.3 计算运动

```python
meters_per_count = math.pi * wheel_diameter_m / counts_per_wheel_rev
left_distance = left_delta * meters_per_count
right_distance = right_delta * meters_per_count
center_distance = 0.5 * (left_distance + right_distance)
yaw_delta = (right_distance - left_distance) / wheel_track_m
```

### 13.4 累加车轮角度

一整圈是 `2π rad`：

```python
self.left_wheel_angle_rad += (
    left_delta * 2.0 * math.pi / counts_per_wheel_rev
)
```

本次增加半圈计数，车轮角度就增加 π rad，也就是 180°。

### 13.5 返回结果

```python
return self.sample()
```

`sample()` 把对象的当前状态放入新的 `OdometrySample`，交给主节点。

## 14. 用当前参数计算直行例子

上一批：

```text
left_count=100000
right_count=100000
```

下一批：

```text
left_count=101470
right_count=101470
```

增量均为 1470：

```text
左右轮距离 ≈ 1470 × 0.00000340339
           ≈ 0.005003 m

```

若原来 yaw=0：

```text
x 增加约 0.005003 m

```

## 15. 用当前参数计算转弯例子

假设：

```text
left_delta=1000
right_delta=1200
```

换算：

```text
左轮距离 ≈ 0.00340339 m
右轮距离 ≈ 0.00408407 m
中心距离 ≈ 0.00374373 m
```

轮距 0.162 m：

```text
yaw_delta
= (0.00408407 - 0.00340339) / 0.162
≈ 0.004202 rad
≈ 0.241°
```

右轮更远，因此向左转。单批 y 变化很小，但不断累加后会形成弧线。

## 16. 主节点怎样收到编码器数据

`chassis_can_node.py` 中：

```python
elif frame.can_id == protocol.ID_LEFT_ENCODER:
    decoded = protocol.decode_encoder(frame)
    if decoded is not None:
        self._left_encoder = decoded
        self._update_odometry_if_pair_ready()
```

右轮逻辑相同。

`elif` 表示前面的帧类型不匹配时继续判断。`decode_encoder()` 会检查 ID 和 CRC。坏帧返回 `None`，不会进入里程计。

解码结果：

```python
@dataclass
class EncoderData:
    total_count: int
    delta_count: int
    sequence: int
```

解码格式：

```python
total, delta, sequence = struct.unpack("<ihB", frame.data[:7])
```

含义：

```text
<  小端序
i  4 字节有符号累计计数
h  2 字节有符号增量
B  1 字节无符号 sequence
第 8 字节为 CRC
```

## 17. 为什么左右编码器必须配对

STM32 同一批左右帧使用相同 `sequence`。RDK：

```python
if left is None or right is None or left.sequence != right.sequence:
    return
```

只有左右都存在且批次相同才计算。

如果左轮来自第 20 批、右轮来自第 21 批，两侧对应时间不同，会制造虚假轮差和错误转角。

还要防止同一批重复处理：

```python
if self._last_odometry_sequence == left.sequence:
    return
```

这防止同一对累计计数被重复累加。

## 19. `/odom` 是什么

话题 `/odom` 的消息类型：

```text
nav_msgs/msg/Odometry
```

主要字段：

```text
header              时间戳和父坐标系
child_frame_id      子坐标系
pose.pose           位置和姿态
pose.covariance     位姿不确定性
twist.twist         线速度和角速度
twist.covariance    速度不确定性
```

创建发布者：

```python
self._odom_publisher = self.create_publisher(
    Odometry, "odom", 20
)
```

最后的 20 是 QoS 队列深度，不是直接指定 20 Hz。不过当前编码器遥测约 20 Hz，因此 `/odom` 正常也接近 20 Hz。

## 20. 时间戳和坐标系

```python
stamp = self.get_clock().now().to_msg()
odom.header.stamp = stamp
odom.header.frame_id = odom_frame
odom.child_frame_id = base_frame
```

当前：

```text
odom_frame=odom
base_frame=base_link
```

消息表达：

```text
在 odom 坐标系中，base_link 当前的位置、姿态和速度。
```

`odom` 是局部连续坐标系，短时间平滑但长期漂移。`base_link` 固定在车体上，跟着小车移动。

## 21. 位姿怎样写入 `/odom`

位置：

```python
odom.pose.pose.position.x = sample.x_m
odom.pose.pose.position.y = sample.y_m
```

姿态字段使用四元数，而不是直接填 yaw：

```python
half_yaw = 0.5 * sample.yaw_rad
quaternion_z = math.sin(half_yaw)
quaternion_w = math.cos(half_yaw)
```

二维纯 yaw：

```text
qx=0
qy=0
qz=sin(yaw/2)
qw=cos(yaw/2)
```

四元数适合三维旋转运算。初学阶段不必推导完整理论，只需知道这里完成了从二维 yaw 到 ROS 姿态格式的转换。

## 22. `/odom` 的速度从哪里来

这是当前代码中最容易混淆的一点。

### 22.1 位姿来源

```text
x、y、yaw
来源：累计编码器计数 → wheel_odometry.py
```

### 22.2 速度来源

```text
linear.x、angular.z
来源：STM32 上传的左右实测轮速帧 0x181
```

线速度：

```python
odom.twist.twist.linear.x = 0.5 * (
    left_measured + right_measured
)
```

```text
车体线速度 = (左轮实测速度 + 右轮实测速度) / 2
```

角速度：

```text
车体角速度 = (右轮实测速度 - 左轮实测速度) / 轮距
```

STM32 以 100 Hz 根据编码器增量计算轮速并低通滤波，约 50 Hz 上传。RDK 保存最新轮速，在编码器批次发布 `/odom` 时填入速度字段。

## 23. `/joint_states` 是什么

类型：

```text
sensor_msgs/msg/JointState
```

当前关节：

```text
left_wheel_joint
right_wheel_joint
```

累计轮角：

```python
joint.position = [
    sample.left_wheel_angle_rad,
    sample.right_wheel_angle_rad,
]
```

轮角速度由：

```text
角速度 = 线速度 / 轮半径
```

计算。`/joint_states` 常用于 RViz 车轮动画和 `robot_state_publisher`，它是状态输出，不是电机控制命令。

## 24. TF 是什么

TF 管理坐标系关系。当前发布：

```text
odom → base_link
```

主节点将与 `/odom` 相同的 x、y 和四元数写入 `TransformStamped`，再调用：

```python
self._tf_broadcaster.sendTransform(transform)
```

### 24.1 为什么有 `/odom` 还要 TF

`/odom` 是包含位姿和速度的数据消息。TF 专门让 ROS 中其他模块查询任意坐标系之间的关系。导航、RViz 和传感器坐标变换依赖 TF 树。

### 24.2 不要重复发布同一 TF

同一时刻只应有一个来源发布 `odom → base_link`。以后使用 EKF 融合编码器和 IMU 时，通常由融合节点发布最终 TF，而原始轮式里程计只提供数据，这时要考虑关闭本节点的 `publish_tf`。

## 25. `map`、`odom`、`base_link` 的区别

```text
map        全局地图坐标系，可由定位算法修正
odom       局部连续坐标系，短时平滑但长期漂移
base_link  车体坐标系，跟着小车移动
```

常见 TF 链：

```text
map → odom → base_link → 传感器坐标系
```

当前编码器模块只提供 `odom → base_link`。它不是地图定位，不知道小车在房间地图里的绝对位置。

## 26. STM32 重启时怎样处理

STM32 重启后累计编码器通常回到零。RDK 比较心跳 `uptime_ms`：

```python
if heartbeat.uptime_ms < self._previous_stm32_uptime_ms:
    self._odometry.reset()
    self._last_odometry_sequence = None
```

运行时间突然变小意味着 STM32 重启。RDK 清空里程计，让下一对计数重新建立基准，避免把大计数跳到零误认为巨大反向运动。

代价是当前 `/odom` 回到原点。系统尚未实现 STM32 重启后保持全局位姿。

## 27. 手动复位里程计

底盘静止并失能时：

```bash
ros2 service call /chassis/reset_odometry \
  std_srvs/srv/Trigger "{}"
```

流程：

1. RDK 检查 STM32 不在 `RUNNING`；
2. RDK 发送复位系统命令；
3. STM32 清累计计数；
4. RDK 调用 `self._odometry.reset()`；
5. 下一对编码器重新建立基准。

## 31. 参数错误的表现

### 31.1 轮径错误

轮径写得比实际大，同样计数被换算成更远距离，`/odom` 偏大；反之偏小。

### 31.2 每圈计数错误

参数比真实值小，软件认为较少计数就是一圈，里程偏大；参数比真实值大，里程偏小。

### 31.3 轮距错误

```text
yaw_delta = 左右距离差 / 轮距
```

轮距写小，转角偏大；轮距写大，转角偏小。

### 31.4 方向错误

若小车向前时一侧计数正、另一侧负，里程计会认为车在旋转。当前正方向修正在 STM32 接口层，RDK 正常应收到“向前均为正”的计数。

## 32. 标定基本思路

### 32.1 直线距离

低速走一段较长且可测的直线。若确认每圈计数理论值正确，可先按比例修正轮径：

```text
新轮径 = 旧轮径 × 实际距离 / 里程计距离
```

例如实际 2.0 m，里程计 1.9 m：

```text
新轮径 ≈ 0.065 × 2.0 / 1.9
       ≈ 0.06842 m
```

### 32.2 转角

比较实际转角和里程计 yaw，可用以下比例作为迭代起点：

```text
新轮距 = 旧轮距 × 里程计转角 / 实际转角
```

阿克曼车还受舵角标定、轴距和侧滑影响，应多做左右转弯、低速重复实验，不能只测一次。

## 33. 为什么里程计会漂移

主要误差来源：

1. 轮胎打滑；
2. 地面不平；
3. 左右轮实际直径不同；
4. 轮径、轮距和计数参数不准；
5. 阿克曼转向侧滑；
6. 机械间隙和轮胎形变；
7. 编码器漏计或干扰；
8. 车轮架空转动；
9. 小车被抱起换位置。

编码器只知道轮子转了多少，不知道轮胎相对地面是否真的移动了同样距离。

## 34. 当前里程计与 IMU 的关系

当前事实：

```text
/odom 的 x、y、yaw 来自编码器
当前没有 /imu/data
当前没有编码器 + IMU 融合
```

IMU 陀螺仪能测车体角速度，短时间转动响应直接，但积分会因零偏漂移。编码器和 IMU 可以互补。

后续完整链路应是：

1. STM32 完成可靠 IMU 校准；
2. 增加 IMU 串口报文；
3. RDK 换成 SI 单位并发布 `sensor_msgs/msg/Imu`；
4. 标定 IMU 到 `base_link` 的坐标变换；
5. 为轮式里程计和 IMU 设置合理协方差；
6. 使用 `robot_localization` EKF 融合；
7. 由融合节点发布最终 `odom → base_link` TF。

## 35. 当前实现的边界

### 35.1 协方差尚未专门填写

`Odometry` 有位姿和速度协方差，用于描述不确定性。当前保持默认值。以后接入 EKF 前，应通过实车误差测试设置合理协方差。全零不代表真实里程计没有误差。

### 35.2 只做二维运动

当前只计算 x、y、yaw，没有 z、roll、pitch。

### 35.3 不是地图定位

它不识别墙、地图或绝对位置。抱起小车换地方时，编码器可能完全不知道。

### 35.4 使用左右轮行程差模型

对阿克曼车，在理想无侧滑时也能由左右驱动轮行程差估计 yaw；实际急转弯、舵角误差和轮胎侧滑会增加误差。

## 36. 常见问题排查

### 36.1 没有 `/odom`

```bash
ros2 node list
ros2 topic list
ros2 topic info /odom -v
ros2 topic echo --once /diagnostics
```

若心跳正常但没有 `/odom`，检查左右编码器帧是否都收到、sequence 是否能配对。

### 36.2 `/odom` 不变化

可能是车轮没转、编码器异常、STM32 没上传、左右无法配对或几何参数非法。

可同时看：

```bash
ros2 topic echo /motor/debug
ros2 topic echo /joint_states
```

实测轮速变化但关节位置不变时，重点检查累计编码器遥测链。

### 36.3 直行时 yaw 持续变化

可能是左右比例不同、某侧打滑、轮胎直径不同、参数错误或左右帧配对异常。

### 36.4 前进时 x 减小

正方向约定反了。先检查 STM32 编码器符号，不要在 RDK 公式里随意乘负号。

### 36.5 `/odom` 突然归零

可能手动复位了里程计、RDK 节点重启，或 STM32 重启被心跳检测到。

### 36.6 数据跳动或重复

检查是否重复启动两个节点：

```bash
pgrep -af 'chassis_serial.launch.py|chassis_can_node'
```

两个节点会抢串口并同时发布同名 `/odom` 和 TF。

## 38. 用一条主线记住整个模块

```text
STM32 上传左右累计编码器计数
→ Python 协议模块解码
→ 主节点按 sequence 配成同一批
→ WheelOdometry 计算计数差
→ 计数差换算左右距离
→ 左右平均得到中心距离
→ 左右距离差除轮距得到 yaw 变化
→ 用中点角把距离分解到 x、y
→ 累加左右轮角度
→ 主节点发布 /odom、/joint_states 和 odom→base_link TF
```

如果你能把这条主线和代码函数一一对应，就已经真正理解了编码器里程计模块的整体实现。
