# 单轮电机闭环控制模块逐行深入讲解

## 1. 文档范围

本文只集中讲当前 STM32 下位机工程中的“单轮电机速度闭环控制模块”，核心文件是：

```text
keil_project/R550_C30D_SERIAL_MOTOR/
└── CHASSIS_SERIAL/
    ├── inc/wheel_controller.h
    └── src/wheel_controller.c
```

但这个模块不是孤立运行的。为了说明它的输入从哪里来、输出到哪里去，还会涉及：

```text
CHASSIS_SERIAL/src/chassis_tasks.c       100 Hz 周期任务
CHASSIS_SERIAL/src/chassis_app.c         运动学、安全状态机、编码器预处理
CHASSIS_SERIAL/inc/chassis_params.h      控制参数结构体
CHASSIS_SERIAL/src/chassis_params.c      默认值与参数检查
CHASSIS_SERIAL/src/c30d_chassis_port.c   控制算法与硬件之间的接口
HARDWARE/encoder.c                       编码器计数
BALANCE/balance.c                        Set_Pwm() 最终输出
```

当前左右轮分别拥有一个 `wheel_controller_t` 对象，运行完全相同的算法，只是输入、状态和参数分别保存。因此理解一个轮子的控制器，就理解了左右两套速度环。

## 2. 这个模块究竟解决什么问题

上层能够给出“左轮应该以 0.20 m/s 前进”，但是电机驱动电路真正接受的不是 m/s，而是一个正负 PWM 数值。

单轮闭环模块要完成的工作是：

```text
目标轮速 target_mps
        ↓
与编码器实测速度比较
        ↓
计算速度误差
        ↓
前馈 + 死区 + P + I
        ↓
限制在硬件允许范围
        ↓
输出有符号 PWM
```

它还负责：

- 对编码器速度做低通滤波；
- 对目标速度做加减速斜坡；
- 输出禁止时清理会造成冲击的历史状态；
- 目标回零后清除积分；
- 防止积分饱和；
- 保存目标、实测、误差、积分和 PWM，供下一周期继续使用。

它不负责：

- 从 `/cmd_vel` 计算左右轮目标；
- 直接读取定时器编码器；
- 判断电池是否欠压；
- 判断命令是否超时；
- 判断是否堵转；
- 直接写 STM32 PWM 寄存器。

这些工作分别由调用它之前和之后的模块完成。

## 3. 为什么必须使用闭环

### 3.1 开环控制

最简单的电机程序可能是：

```c
Set_Pwm(3000, 0, 0, 0, 0);
```

这相当于告诉驱动器“给电机一个固定 PWM”，但程序不知道电机实际转多快。它属于开环控制：

```text
PWM命令 → 电机
```

没有反馈返回控制器。

同样的 PWM 在以下情况下速度都会不同：

- 电池满电和电量较低；
- 车轮架空和落地；
- 平地和上坡；
- 左右电机制造差异；
- 轮胎摩擦变化；
- 小车载重变化；
- 齿轮箱磨损或温度变化。

所以不能简单认为“PWM 3000 就等于 0.2 m/s”。

### 3.2 闭环控制

闭环增加编码器反馈：

```text
              ┌────────────编码器实测速度────────────┐
              ↓                                      │
目标速度 → 比较误差 → 控制器 → PWM → 驱动器 → 电机 ──┘
```

控制器每 10 ms 比较一次：

```text
速度误差 e = 目标速度 r - 实测速度 y
```

- 实测偏慢：误差为正，倾向于增加 PWM；
- 实测偏快：误差为负，倾向于降低 PWM；
- 方向相反：误差绝对值更大，控制器会纠正；
- 目标为零：控制器最终输出零。

闭环的目的不是让误差在每一个离散采样点都绝对等于零，而是让系统稳定、快速、平滑地跟踪目标，并在负载变化后恢复。

## 4. 认识“被控对象”与控制量

控制理论中常见几个概念：

| 名称 | 本项目中的对应内容 |
|---|---|
| 设定值/参考值 `r` | 斜坡处理后的目标轮速，m/s |
| 被控量 `y` | 低通滤波后的编码器轮速，m/s |
| 误差 `e` | `r - y`，m/s |
| 控制器 | 前馈 + PI + 死区 + 限幅 |
| 控制量 `u` | 有符号 PWM 计数 |
| 被控对象 Plant | 驱动电路、电机、减速箱、车轮和负载 |
| 传感器 | 正交编码器 |
| 扰动 | 坡度、摩擦、载重、电池变化等 |

这里的“单轮控制器”只控制轮速，不直接控制小车的 `x/y` 位置，也不直接控制整个车体的角度。

## 5. 整个调用链

一次 10 ms 控制周期的真实链路如下：

```text
chassis_control_task()                         chassis_tasks.c
  ├─计算真实 dt_s
  ├─读取左、右编码器增量
  └─调用 chassis_app_control_step()           chassis_app.c
       ├─编码器增量 → 原始轮速
       ├─拒绝不合理的编码器尖峰
       ├─状态机计算 output_allowed
       ├─车体 v、w → 左右目标轮速
       ├─直行同步修正目标
       ├─调用左轮 wheel_controller_update()   wheel_controller.c
       ├─调用右轮 wheel_controller_update()
       ├─用控制器状态检查堵转
       └─返回左右 PWM
  └─c30d_port_set_output()                    c30d_chassis_port.c
       └─Set_Pwm()                            balance.c
            └─写 PWM 比较寄存器和方向
```

这个顺序非常重要：

1. 上层先决定“是否允许输出”；
2. 再决定“这个轮子的目标速度是多少”；
3. 单轮控制器才决定“需要多少 PWM”；
4. 返回后还要做堵转保护；
5. 最后才写硬件。

## 6. 头文件中的控制器状态结构体

`wheel_controller.h`：

```c
typedef struct
{
    float ramped_target_mps;
    float filtered_speed_mps;
    float integral_output;
    float last_error_mps;
    int16_t output_pwm;
} wheel_controller_t;
```

这个结构体不是“参数”，而是一个控制器在运行过程中的记忆。

### 6.1 `ramped_target_mps`

经过加减速限制后的当前目标速度，单位 m/s。

上层可能突然要求从 0 跳到 0.6 m/s，但本变量会按每周期允许的步长逐渐变化：

```text
0.000 → 0.005 → 0.010 → 0.015 → ...
```

下一周期必须知道上一周期斜坡走到哪里，因此要保存在结构体中。

### 6.2 `filtered_speed_mps`

编码器实测速度经过一阶低通滤波后的结果，单位 m/s。

它也是递推计算：

```text
新滤波值 = 旧滤波值 + α × (新测量值 - 旧滤波值)
```

所以必须保存旧值。

### 6.3 `integral_output`

积分项已经累积出的 PWM 贡献。

注意它保存的不是单纯的“误差总和”，而是已经乘过 `Ki` 和 `dt` 的输出量，单位可以理解为 PWM 计数：

```text
I[k] = I[k-1] + Ki × e[k] × dt
```

### 6.4 `last_error_mps`

最近一次速度误差，单位 m/s。

当前控制公式没有 D 项，所以它不是为了计算误差微分；主要用于回传给 RDK 的 `/motor/debug`，帮助观察跟踪效果。

### 6.5 `output_pwm`

当前最终 PWM，16 位有符号整数。

- 正值：一个方向；
- 负值：相反方向；
- 0：不驱动。

具体正负方向最后还受到 `c30d_chassis_port.h` 中方向符号配置以及实际接线影响。

### 6.6 左右轮为什么必须有两份状态

`chassis_app_t` 中：

```c
wheel_controller_t left_controller;
wheel_controller_t right_controller;
```

左右轮的实测速度、负载、积分历史和 PWM 都不相同。如果两轮共用一个 `integral_output`，一侧误差会错误地影响另一侧。

## 7. 控制参数结构体

单轮专属参数：

```c
typedef struct
{
    float kp;
    float ki;
    float kff;
    float dead_forward;
    float dead_reverse;
    int16_t output_limit;
} wheel_control_params_t;
```

当前左右轮默认相同：

```text
Kp = 3000
Ki = 1500
Kff = 9000
正转死区 = 700
反转死区 = 700
PWM限制 = 16700
```

但结构设计允许左右轮分别标定。

共享参数来自 `chassis_params_t`：

```text
maximum_linear_speed_mps = 0.60 m/s
acceleration_mps2 = 0.50 m/s²
deceleration_mps2 = 0.80 m/s²
speed_filter_alpha = 0.35
```

### 7.1 参数单位

| 参数 | 近似单位 | 意义 |
|---|---|---|
| `kp` | PWM/(m/s) | 每 1 m/s 当前误差增加多少 PWM |
| `ki` | PWM/(m/s·s) | 误差每持续 1 秒积累多少 PWM |
| `kff` | PWM/(m/s) | 根据目标速度预估基础 PWM |
| `dead_forward/reverse` | PWM | 克服正/反转静摩擦的基础量 |
| `output_limit` | PWM | 控制器最大绝对输出 |
| `acceleration_mps2` | m/s² | 目标加速斜率 |
| `deceleration_mps2` | m/s² | 目标减速/换向斜率 |
| `speed_filter_alpha` | 无量纲 | 实测速度滤波权重 |

这些单位帮助理解：如果改变速度单位，例如从 m/s 改为 mm/s，却不重新换算参数，Kp、Ki、Kff 将全部不再合适。

## 8. `wheel_controller_update()` 的接口

```c
int16_t wheel_controller_update(
    wheel_controller_t *controller,
    const wheel_control_params_t *control_params,
    const chassis_params_t *chassis_params,
    float target_mps,
    float measured_mps,
    float dt_s,
    uint8_t allow_output);
```

逐个解释：

### 8.1 `controller`

当前轮子的运行状态地址。函数会修改其中的斜坡目标、滤波速度、积分和 PWM。

左轮调用传：

```c
&app->left_controller
```

右轮调用传：

```c
&app->right_controller
```

### 8.2 `control_params`

当前轮子的专属参数，只读，因此使用 `const`：

```c
&app->params.left
```

### 8.3 `chassis_params`

包含最大速度、斜坡、滤波等两轮共享参数，同样只读。

### 8.4 `target_mps`

上层运动学和直行同步修正后，这个轮子最终想要达到的速度。

它不是原始 `/cmd_vel.linear.x`。转弯时左右轮目标通常不同。

### 8.5 `measured_mps`

由本周期编码器增量换算的轮速。如果上层发现编码器本次速度超过物理上限，则不会把异常值传入，而是把控制器上一周期的滤波值作为本次测量值。

这会使滤波公式得到：

```text
measured = filtered_old
filtered_new = filtered_old + α × (filtered_old - filtered_old)
             = filtered_old
```

即在单次尖峰时保持上一可信值。

### 8.6 `dt_s`

真实控制周期，正常约 0.01 s。积分和斜坡都依赖它。

上层先检查：

```text
0.005 s ≤ dt ≤ 0.020 s
```

明显异常时记录 `CONTROL_OVERRUN`，并使用 0.010 s 代替，避免一个过大的 dt 让积分突然跳变。

### 8.7 `allow_output`

由上层安全状态机生成：

```text
1：状态为 RUNNING，允许控制
0：IDLE/TIMEOUT/FAULT/ESTOP 等，不允许控制
```

这个值不是单纯的软件使能按钮，还综合了硬件使能、命令超时、急停和严重故障。

### 8.8 返回值

返回最终有符号 PWM，类型 `int16_t`。上层保存为：

```c
app->left_pwm
app->right_pwm
```

## 9. 辅助函数一：`clamp_float()`

```c
static float clamp_float(float value,
                         float minimum,
                         float maximum)
{
    if (value > maximum)
        return maximum;
    if (value < minimum)
        return minimum;
    return value;
}
```

`clamp` 意思是限幅或夹紧：

```text
clamp(5, 0, 10)   = 5
clamp(20, 0, 10)  = 10
clamp(-3, 0, 10)  = 0
```

本模块有两处重要使用：

1. 将单轮目标限制在最大线速度内；
2. 将总 PWM 限制在 `±output_limit` 内。

为什么即使上层已经限制过目标，这里还要再限制？这是防御式设计：单轮函数不完全相信调用者，避免未来别的模块直接调用时给出过大目标。

## 10. 辅助函数二：`approach_target()`

函数作用是让当前斜坡目标逐步靠近最终目标：

```c
static float approach_target(float current,
                             float target,
                             float acceleration,
                             float deceleration,
                             float dt_s)
```

### 10.1 先计算还差多少

```c
float difference = target - current;
```

例如：

```text
current = 0.10
target = 0.30
difference = 0.20 m/s
```

### 10.2 判断加速还是减速

代码将下面两种情况看作加速：

```text
当前和目标都非负，并且目标更大
当前和目标都非正，并且目标更负
```

第二种也是加速，因为速度绝对值变大：

```text
-0.10 → -0.30
```

其他情况使用减速度，包括：

- 正向速度降低；
- 反向速度绝对值降低；
- 正转切换到反转；
- 反转切换到正转。

### 10.3 每周期允许变化多少

```c
limit = acceleration * dt_s;
```

或：

```c
limit = deceleration * dt_s;
```

当前 `dt=0.01 s`：

```text
加速步长 = 0.50 × 0.01 = 0.005 m/s/周期
减速步长 = 0.80 × 0.01 = 0.008 m/s/周期
```

### 10.4 限制差值

如果目标只差 0.003 m/s，小于 0.005，就直接到目标，不会越过目标。

如果还差 0.20 m/s，本周期只走 0.005。

```c
return current + difference;
```

### 10.5 为什么减速度大于加速度

当前选择：

```text
加速 0.50 m/s²
减速 0.80 m/s²
```

目的是启动相对柔和，而正常停车和换向前的减速更快。它不是紧急停止的唯一手段；发生急停或安全禁止时，`allow_output=0` 会直接返回零 PWM，不等待斜坡慢慢下降。

### 10.6 从 0 到 0.30 m/s 要多久

理想斜坡时间：

```text
t = Δv / a = 0.30 / 0.50 = 0.60 s
```

100 Hz 下大约 60 个周期。

## 11. `wheel_controller_reset()` 深入讲解

```c
void wheel_controller_reset(wheel_controller_t *controller)
{
    if (controller != 0)
    {
        memset(controller, 0, sizeof(*controller));
    }
}
```

### 11.1 为什么检查空指针

`controller != 0` 确认地址有效。若对空地址执行 `memset`，MCU 可能进入 HardFault。

### 11.2 `sizeof(*controller)`

表示指针所指向结构体的大小，而不是指针本身大小。这样即使以后给结构体增加字段，也会自动清完整个结构体。

### 11.3 `memset(..., 0, ...)`

把结构体的所有字节清零，因此五个状态全部归零：

```text
ramped_target_mps = 0
filtered_speed_mps = 0
integral_output = 0
last_error_mps = 0
output_pwm = 0
```

### 11.4 什么时候完整复位

当前代码会在以下场景调用完整复位：

- 底盘应用初始化；
- 清除故障；
- 成功修改控制参数后；
- 发现堵转并撤销输出。

修改参数后复位很重要。例如 Ki 改变后，旧 `integral_output` 是由旧参数形成的，直接保留可能产生突变。

## 12. `wheel_controller_update()` 第一步：入口保护

```c
if ((controller == 0) ||
    (control_params == 0) ||
    (chassis_params == 0) ||
    (dt_s <= 0.0f))
{
    return 0;
}
```

目的：

- 防止空指针访问；
- 防止 `dt=0` 或负数进入积分和斜坡；
- 异常时输出零比继续计算更安全。

上层还会过滤 NaN 和明显异常的 dt。这一层仍保留最基本的保护。

## 13. 第二步：实测速度低通滤波

代码：

```c
controller->filtered_speed_mps +=
    chassis_params->speed_filter_alpha *
    (measured_mps - controller->filtered_speed_mps);
```

写成数学公式：

```text
y_f[k] = y_f[k-1] + α × (y[k] - y_f[k-1])
```

也可以整理为：

```text
y_f[k] = α × y[k] + (1-α) × y_f[k-1]
```

当前 `α=0.35`：

```text
新测量占 35%
旧滤波值占 65%
```

### 13.1 为什么编码器速度会抖

控制周期内编码器只能得到整数计数。以当前参数：

```text
轮径 D = 0.065 m
每轮计数 N = 60000
周期 dt = 0.01 s
```

一个计数对应本周期速度分辨率约：

```text
(π × 0.065 / 60000) / 0.01
≈ 0.000340 m/s
```

实际计数还会受边沿时刻、机械振动和电气干扰影响，所以连续周期可能略有跳动。

### 13.2 数值示例

假设旧滤波值为 0.040 m/s，新测量为 0.060 m/s：

```text
新滤波值 = 0.040 + 0.35 × (0.060 - 0.040)
           = 0.047 m/s
```

没有直接跳到 0.060，因此 P 项和 PWM 不会因为一次测量变化而剧烈跳动。

### 13.3 α 如何影响系统

- α 接近 1：接近原始测量，响应快，噪声大；
- α 较小：更平滑，响应慢，反馈延迟大；
- α 不能设成 0，否则滤波值永远不更新。

当前参数验证范围是 `0.01～1.0`。

以 10 ms 周期、α=0.35 粗略估计，滤波时间常数约 23 ms，属于较轻的滤波。实际效果仍应通过 `/motor/debug` 观察。

### 13.4 为什么先滤波，再判断 `allow_output`

代码即使在失能时仍更新 `filtered_speed_mps`。这样车轮因惯性继续转动时，控制器仍能跟踪实际轮速。

但失能分支不会清除 `filtered_speed_mps`，只清斜坡、积分、误差和 PWM。这和 `wheel_controller_reset()` 的完整清零不同。

## 14. 第三步：安全禁止分支

```c
if (allow_output == 0U)
{
    controller->ramped_target_mps = 0.0f;
    controller->integral_output = 0.0f;
    controller->last_error_mps = 0.0f;
    controller->output_pwm = 0;
    return 0;
}
```

### 14.1 为什么立即返回

当上层状态机不允许输出时，安全逻辑优先于斜坡和 PI，不再计算任何驱动 PWM。

这可能发生在：

- 尚未收到命令；
- RDK 没有软件使能；
- 硬件使能关闭；
- 命令超时；
- 急停；
- 欠压、编码器、堵转或参数故障。

### 14.2 为什么清斜坡目标

假设失能前斜坡目标是 0.4 m/s。如果不清，重新使能时会从 0.4 附近继续，可能突然产生很大输出。清零后重新使能必须从 0 开始加速。

### 14.3 为什么清积分

积分代表过去为了克服负载累积的输出。失能期间系统条件可能已经变化，保留旧积分会导致重新使能时冲击，这种现象叫无扰切换问题。当前做法选择安全的“从零重新建立”。

## 15. 第四步：目标限幅

```c
target_mps = clamp_float(
    target_mps,
    -chassis_params->maximum_linear_speed_mps,
    chassis_params->maximum_linear_speed_mps);
```

当前最大值 0.60 m/s，因此单轮输入被限制在：

```text
-0.60 ≤ target_mps ≤ +0.60
```

负号不是非法值，表示反转。

上层在左右轮运动学之后也会等比例缩小超限目标；本函数再次限幅形成第二道保护。

## 16. 第五步：更新斜坡目标

```c
controller->ramped_target_mps = approach_target(
    controller->ramped_target_mps,
    target_mps,
    chassis_params->acceleration_mps2,
    chassis_params->deceleration_mps2,
    dt_s);
```

这里要区分两个目标：

```text
target_mps          上层最终要求，可能瞬间变化
ramped_target_mps   当前周期控制器真正跟踪的平滑目标
```

PI 使用的是 `ramped_target_mps`，不是原始 `target_mps`。

这样可以减少：

- 启动电流冲击；
- 减速箱机械冲击；
- 轮胎突然打滑；
- 误差瞬间变大导致 P 项跳变；
- PWM 从正最大突然变负最大。

## 17. 第六步：零目标特殊处理

```c
if ((fabsf(target_mps) < 0.001f) &&
    (fabsf(controller->ramped_target_mps) < 0.002f))
{
    controller->ramped_target_mps = 0.0f;
    controller->integral_output = 0.0f;
    controller->last_error_mps = -controller->filtered_speed_mps;
    controller->output_pwm = 0;
    return 0;
}
```

### 17.1 为什么有两个阈值

- 最终目标必须接近零；
- 斜坡目标也已经减速到接近零。

如果最终目标刚变成 0，但斜坡目标仍是 0.2，说明正在按减速度停车，此时仍允许控制器沿斜坡减速。

### 17.2 为什么不要求浮点数精确等于 0

浮点计算可能产生极小残差，例如 `0.00000003`。使用绝对值阈值更可靠。

### 17.3 为什么目标回零后直接 PWM=0

如果继续运行 PI，编码器微小噪声会产生误差，积分可能为了维持“数学上的零速度”持续给电机小电流，引起：

- 嗡鸣或啸叫；
- 电机发热；
- 车轮轻微抖动；
- 静止耗电。

本项目更重视静止时彻底断开控制输出。

### 17.4 `last_error_mps` 为什么设为负滤波速度

目标为零时，理论误差是：

```text
error = 0 - filtered_speed
```

虽然不继续计算 PWM，仍把这个真实误差保存，供调试数据观察车轮是否还因惯性转动。

## 18. 第七步：方向相关死区补偿

```c
if (ramped_target > 0)
    deadzone = dead_forward;
else if (ramped_target < 0)
    deadzone = -dead_reverse;
```

### 18.1 什么是电机死区

由于静摩擦、齿轮摩擦、驱动管压降等原因，PWM 从 0 增大时，电机通常不会立刻转。可能出现：

```text
PWM 0～600：不转
PWM 700 附近：开始克服摩擦
```

这段“给了控制量却几乎没有运动”的区域叫死区。

### 18.2 为什么正反转死区分开

机械装配、碳刷、齿轮和驱动电路可能让正反转起转阈值不同，因此结构体分别保存：

```text
dead_forward
dead_reverse
```

### 18.3 为什么反转死区要取负

反转目标需要负 PWM，所以基础补偿也必须为负。否则目标为负时却加正补偿，会削弱甚至抵消反转输出。

### 18.4 死区补偿的风险

死区过小：低速目标可能不转，积分慢慢堆积后才突然起转。

死区过大：刚有很小目标就给很大 PWM，产生低速跳跃和冲击。

死区应通过架空和落地低速实验分别标定正反方向。

## 19. 第八步：计算速度误差

```c
error = ramped_target_mps - filtered_speed_mps;
```

这是整个反馈闭环的核心。

| 情况 | 误差符号 | 控制趋势 |
|---|---:|---|
| 正向目标，实际偏慢 | 正 | 增加正向输出 |
| 正向目标，实际偏快 | 负 | 减少正向输出 |
| 反向目标，实际反向不够快 | 负 | 增加负向输出 |
| 反向目标，实际反向过快 | 正 | 减少负向输出 |

例如反转：

```text
目标 = -0.20
实测 = -0.10
误差 = -0.20 - (-0.10) = -0.10
```

负误差会产生负 P 项，使反向驱动力增加。

## 20. 第九步：前馈控制

```c
feedforward = kff * ramped_target_mps + deadzone;
```

### 20.1 什么是前馈

反馈 PI 必须先看到误差才会行动。前馈则根据目标直接预估需要多少输出：

```text
目标轮速 → 经验模型 → 预计PWM
```

如果知道空载下大致有：

```text
PWM ≈ Kff × 目标速度 + 死区
```

就可以先给出大部分所需输出，PI 只负责修正负载、电池和模型误差。

### 20.2 当前数值例子

目标斜坡为 0.05 m/s：

```text
Kff = 9000 PWM/(m/s)
dead_forward = 700 PWM
```

```text
feedforward = 9000 × 0.05 + 700
            = 1150 PWM
```

反向 -0.05 m/s：

```text
feedforward = 9000 × (-0.05) - 700
            = -1150 PWM
```

### 20.3 前馈不是闭环反馈

如果只剩前馈，系统本质上仍近似开环，因为它不看实测误差。真正抵抗负载变化的是后面的 P 和 I。

### 20.4 为什么前馈能减轻积分负担

没有前馈时，控制器可能需要依靠误差和积分慢慢建立几千 PWM。加入较准确前馈后，电机一开始就接近正确工作点，误差更小，响应更快。

## 21. 第十步：比例项 P

```c
proportional = kp * error;
```

数学表达：

```text
P[k] = Kp × e[k]
```

### 21.1 比例项的直觉

误差越大，纠正力度越大。误差为零，P 项为零。

当前 `Kp=3000`：

```text
误差 0.01 m/s → P = 30 PWM
误差 0.10 m/s → P = 300 PWM
误差 -0.05 m/s → P = -150 PWM
```

### 21.2 Kp 太小

- 负载变化后恢复慢；
- 实测速度长期明显偏离目标；
- 控制感觉软。

### 21.3 Kp 太大

- PWM 对编码器噪声过于敏感；
- 速度来回振荡；
- 电机声音尖锐；
- 机械冲击和电流增大；
- 离散采样和延迟可能使系统不稳定。

### 21.4 为什么 P 通常不能消除所有稳态误差

若没有前馈和积分，电机克服负载需要固定 PWM，而 P 项只有存在误差时才产生输出。因此系统可能必须保持一个非零速度误差，才能产生维持负载所需的 PWM。这就是加入 I 项的原因之一。

## 22. 第十一步：积分候选值 I

```c
integral_candidate = integral_output + ki * error * dt_s;
```

离散积分公式：

```text
I[k] = I[k-1] + Ki × e[k] × dt
```

### 22.1 积分的直觉

P 只看“现在差多少”；I 看“误差已经持续了多久”。

若小车上坡后长期比目标慢一点，误差虽然不大，却持续为正，积分会逐步增加 PWM，直到消除稳态误差。

### 22.2 为什么必须乘 `dt`

积分近似误差曲线下的面积。控制频率改变时，每个样本代表的时间不同。

如果不乘 `dt`：

- 100 Hz 每秒累加 100 次；
- 200 Hz 每秒累加 200 次；

同一个 Ki 会因为控制频率变化而效果翻倍。乘以真实 dt 后，参数物理意义更稳定。

### 22.3 当前数值例子

```text
Ki = 1500
error = 0.02 m/s
dt = 0.01 s
```

每周期：

```text
ΔI = 1500 × 0.02 × 0.01 = 0.30 PWM
```

如果误差保持 1 秒，也就是约 100 个周期：

```text
积分大约增加 30 PWM
```

若误差为负，积分会下降。

### 22.4 积分为什么可能危险

假设车轮被卡住：

- 目标始终很大；
- 实测始终为零；
- 误差持续为正；
- 积分不断增加；
- 但 PWM 已经达到硬件上限。

如果积分继续累积，障碍解除后控制器仍保留巨大正输出，会长时间过冲。这叫积分饱和或 windup。

## 23. 第十二步：第一次计算总输出

```c
output_before_limit = feedforward
                    + proportional
                    + integral_candidate;
```

完整控制律：

```text
u_raw = Kff × r
      + deadzone(sign(r))
      + Kp × (r-y)
      + I_candidate
```

其中：

```text
r = ramped_target_mps
y = filtered_speed_mps
```

### 综合例子

假设当前：

```text
r = 0.10 m/s
y = 0.08 m/s
旧积分 = 20 PWM
Kff = 9000
Kp = 3000
Ki = 1500
deadzone = 700
dt = 0.01 s
```

计算：

```text
error = 0.10 - 0.08 = 0.02
feedforward = 9000×0.10 + 700 = 1600
P = 3000×0.02 = 60
I_candidate = 20 + 1500×0.02×0.01 = 20.3
u_raw = 1600 + 60 + 20.3 = 1680.3 PWM
```

## 24. 第十三步：PWM 限幅

```c
output_after_limit = clamp_float(
    output_before_limit,
    -output_limit,
    output_limit);
```

当前绝对上限为 16700：

```text
u_raw = 5000   → u = 5000
u_raw = 20000  → u = 16700
u_raw = -19000 → u = -16700
```

限幅的原因：

- STM32 定时器周期约 16799；
- 驱动器不可能输出超过电池电压的平均电压；
- 避免整数范围和寄存器配置异常；
- 为硬件保留少量边界。

## 25. 第十四步：条件积分抗饱和

代码：

```c
if ((before == after) ||
    ((before > after) && (error < 0)) ||
    ((before < after) && (error > 0)))
{
    integral_output = integral_candidate;
}
```

这是整个函数中最需要深入理解的一段。

### 25.1 情况一：输出没有饱和

```text
before == after
```

例如原始输出 5000，限幅后仍为 5000。说明硬件还有控制余量，允许接受本次积分。

### 25.2 情况二：正向上限饱和

```text
before > after
```

例如：

```text
before = 18000
after = 16700
```

如果 `error > 0`，积分继续增大只会让正饱和更严重，因此不接受候选积分。

如果 `error < 0`，新的积分会减小总输出，有助于从正上限退回来，因此允许更新。

### 25.3 情况三：负向下限饱和

```text
before < after
```

例如：

```text
before = -18000
after = -16700
```

如果 `error < 0`，积分会更加负，不允许。

如果 `error > 0`，积分向正方向恢复，有助于退出负饱和，允许更新。

### 25.4 用表格总结

| 输出状态 | 误差方向 | 是否更新积分 | 原因 |
|---|---:|---|---|
| 未饱和 | 任意 | 是 | 尚有控制余量 |
| 正饱和 | 正 | 否 | 会继续推高正输出 |
| 正饱和 | 负 | 是 | 有助于退出正饱和 |
| 负饱和 | 负 | 否 | 会继续推低负输出 |
| 负饱和 | 正 | 是 | 有助于退出负饱和 |

### 25.5 这种方法的特点

它叫条件积分或积分分离式抗饱和，优点是逻辑简单、计算量小、适合 MCU。

它不是唯一方法。其他方法还有积分单独限幅、反算抗饱和等。当前实现足以避免最典型的积分无限堆积。

## 26. 第十五步：用实际接受的积分重新计算输出

```c
output_before_limit = feedforward
                    + proportional
                    + controller->integral_output;
output_after_limit = clamp_float(...);
```

为什么要算第二次？

第一次使用的是 `integral_candidate`，用于判断本次积分能否接受。如果因为饱和拒绝了候选值，就必须改回旧 `integral_output` 重新计算最终 PWM。

否则即使没有保存候选积分，本周期输出仍然错误地用了它。

## 27. 第十六步：保存误差、四舍五入并返回

```c
controller->last_error_mps = error;
controller->output_pwm = (int16_t)(
    output_after_limit >= 0
    ? output_after_limit + 0.5f
    : output_after_limit - 0.5f);
return controller->output_pwm;
```

### 27.1 为什么加减 0.5

C 将浮点数强制转换成整数时通常向零截断：

```text
(int)10.8  = 10
(int)-10.8 = -10
```

加入正负 0.5 后得到较接近数学四舍五入：

```text
10.8 + 0.5 → 11.3 → 11
-10.8 - 0.5 → -11.3 → -11
```

正负分开处理，避免负数方向舍入错误。

### 27.2 为什么返回 `int16_t`

PWM 最大绝对值 16700，在 `int16_t` 的 `-32768～32767` 范围内。协议上传 PWM 时也使用 16 位有符号整数。

## 28. 一个启动过程的多周期计算示例

为了突出算法，先假设编码器实测始终为 0，旧积分为 0，目标突然变成 0.05 m/s。

> 重要：这是一个用于拆解公式的“电机暂未转动”简化条件，不表示真实小车第二个周期的测速一定仍为零。真实第二周期必须先用编码器新数据更新一阶低通滤波，再用 `error = ramped_target - filtered_speed` 计算误差；如果滤波速度已经大于零，第二周期误差就会小于下面示例中的 `0.010`。详细推导见《18_单轮闭环五个问题补充说明》第 6 节。

当前参数：

```text
dt = 0.01 s
acceleration = 0.50 m/s²
Kff = 9000
Kp = 3000
Ki = 1500
deadzone = 700
```

每周期斜坡增加 0.005 m/s。

### 第 1 个周期

```text
r = 0.005
y = 0
error = 0.005
feedforward = 9000×0.005 + 700 = 745
P = 3000×0.005 = 15
I = 0 + 1500×0.005×0.01 = 0.075
PWM ≈ 760
```

### 第 2 个周期

```text
r = 0.010
error = 0.010
feedforward = 790
P = 30
I = 0.075 + 0.15 = 0.225
PWM ≈ 820
```

### 第 10 个周期

斜坡到达最终目标 0.05 m/s。如果电机仍完全不转：

```text
feedforward = 1150
P = 150
积分也在逐步增长
PWM > 1300
```

真实情况下电机开始转动后，滤波速度上升，误差和 P 项会减小，最终输出在负载所需的平衡点附近稳定。

这个例子也说明：死区会在第一个非零目标周期立即加入，因此低速起步主要由死区和前馈提供基础输出，而不是等待积分长时间累积。

## 29. 停车和换向时会发生什么

### 29.1 正常停车

上层目标从 0.30 变为 0：

```text
ramped_target 每周期最多减少 0.008 m/s
PI 继续跟踪下降的斜坡目标
斜坡接近零后进入零目标特殊分支
积分清零，PWM直接归零
```

### 29.2 安全失能或急停

上层直接让 `allow_output=0`：

```text
不等待减速斜坡
本周期直接 PWM=0
斜坡和积分清零
```

注意“PWM 立即为零”不等于机械制动。电机会怎样减速还取决于 H 桥零输出方式、机械阻力和惯性。

### 29.3 正转切换反转

`approach_target()` 先使用较快的减速度将正斜坡目标向负方向移动，再在进入同向负速度后使用加速度规则扩大负速度绝对值。

这避免原始目标从正值到负值时，PWM 在一个周期内从正驱动突然跳成强负驱动。

## 30. 返回 PWM 后发生什么

### 30.1 堵转检测

`chassis_app.c` 使用单轮控制器公开的状态：

```text
ramped_target_mps
filtered_speed_mps
output_pwm
```

当目标足够大、实测很小或方向相反、PWM 很高，并持续达到阈值时，锁存堵转故障。

当前默认：

```text
|斜坡目标| ≥ 0.15 m/s
|滤波实测| ≤ 0.02 m/s，或方向明显相反
|PWM| ≥ 16700×0.80 ≈ 13360
持续 ≥ 600 ms
```

堵转刚被确认的同一周期：

```text
左右PWM全部置零
状态改为FAULT
左右控制器完整reset
```

堵转保护不在 `wheel_controller.c` 内，但直接使用它产生的变量。

### 30.2 写入硬件接口

控制任务取得 `left_pwm` 和 `right_pwm` 后调用：

```c
c30d_port_set_output(left_pwm, right_pwm, servo_pwm);
```

再调用原厂：

```c
Set_Pwm(left, right, 0, 0, servo);
```

### 30.3 `Set_Pwm()` 的正负方向

以电机 A 为例：

```c
if (motor_a < 0)
{
    PWMA1 = 16799;
    PWMA2 = 16799 + motor_a;
}
else
{
    PWMA2 = 16799;
    PWMA1 = 16799 - motor_a;
}
```

正负值选择两路桥臂哪一路保持高值、哪一路按 PWM 变化，从而改变电机两端的有效电压方向。

因此控制器的 `output_pwm` 不是直接写进某一个 CCR 寄存器，而是作为有符号“电机作用量”交给硬件函数转换。

## 31. 与上层运动学的关系

单轮模块并不知道小车是直行还是转弯，它只收到一个轮子目标。

上层先计算：

```text
left_target  = linear - angular × wheel_track / 2
right_target = linear + angular × wheel_track / 2
```

若当前是阿克曼底盘，还会先用轴距和角速度计算舵角并修正角速度。

直行同步也会在进入单轮控制器之前稍微修改左右目标：

```text
left_target  -= sync_correction
right_target += sync_correction
```

之后左右轮各自闭环跟踪各自的目标。

可以把它理解成两层控制：

```text
车体层：决定左右轮分别该多快
单轮层：让每个轮子实际达到各自目标
```

## 32. 与编码器模块的关系

`encoder.c` 的 `Read_Encoder()` 读取本周期计数后立即清零。上层将计数换成速度：

```text
一圈距离 = π × wheel_diameter
本周期距离 = delta_count × 一圈距离 / counts_per_wheel_rev
速度 = 本周期距离 / dt
```

当前：

```text
wheel_diameter = 0.065 m
counts_per_wheel_rev = 60000
```

如果这两个参数错误，单轮控制器看到的 `measured_mps` 就会按比例错误：

- 轮径设得过大：程序认为车轮速度比实际更快；
- 每圈计数设得过大：程序认为速度比实际更慢。

所以几何/编码器标定错误可能表现得像 PI 参数错误。调 PI 前必须先确认方向、轮径和每圈计数。

## 33. 与安全状态机的关系

`allow_output` 由 `chassis_app_control_step()` 决定。只有状态为 `RUNNING` 才为 1。

状态优先级大致为：

```text
ESTOP
  > 严重FAULT
  > TIMEOUT
  > IDLE
  > RUNNING
```

因此单轮 PI 不需要重复理解每一种故障，只需遵守 `allow_output`。这种设计降低了算法模块与业务状态机的耦合。

## 34. 与参数模块和 RDK 的关系

参数在 STM32 中存放于 `chassis_params_t`。RDK YAML 中对应：

```yaml
controller.left_kp: 3000.0
controller.left_ki: 1500.0
controller.left_kff: 9000.0
controller.right_kp: 3000.0
controller.right_ki: 1500.0
controller.right_kff: 9000.0
controller.left_dead_forward: 700.0
controller.left_dead_reverse: 700.0
controller.filter_alpha: 0.35
limits.acceleration_mps2: 0.50
limits.deceleration_mps2: 0.80
```

参数下发时：

1. RDK 检查基本范围；
2. STM32 再次检查参数 ID 和范围；
3. 运行中拒绝修改；
4. 修改成功后完整复位左右控制器；
5. 只有显式调用保存服务才写入 STM32 Flash。

这种双端检查防止异常上位机数据直接破坏控制器。

## 35. 与 `/motor/debug` 的关系

STM32 每 20 ms 上传：

```text
左斜坡目标
左滤波实测
右斜坡目标
右滤波实测
左右PWM
左右误差
```

RDK 发布：

```bash
ros2 topic echo /motor/debug
```

数组顺序：

| 下标 | 来源 |
|---:|---|
| 0 | `left_controller.ramped_target_mps` |
| 1 | `left_controller.filtered_speed_mps` |
| 2 | `right_controller.ramped_target_mps` |
| 3 | `right_controller.filtered_speed_mps` |
| 4 | `left_pwm` |
| 5 | `right_pwm` |
| 6 | `left_controller.last_error_mps` |
| 7 | `right_controller.last_error_mps` |

它没有直接上传：

- 原始未滤波速度；
- 前馈项；
- P 项；
- 积分项。

如果以后需要深入调参，可以扩展调试协议，但会占用更多串口带宽。

## 36. 如何从调试数据判断控制表现

### 36.1 正常跟踪

```text
目标平滑上升
实测稍后跟随
误差逐渐减小
PWM没有长期顶到±16700
目标归零后PWM归零
```

### 36.2 Kp 可能过小

```text
目标变化后实测跟随很慢
负载变化后误差长期较大
PWM修正不积极
```

但也要先排除 Kff 太小、死区太小和电池问题。

### 36.3 Kp 可能过大

```text
实测围绕目标快速来回摆动
PWM正负或大小频繁跳动
电机声音尖锐
```

也可能是滤波太弱、编码器方向/计数异常或机械间隙。

### 36.4 Ki 可能过小

```text
系统基本稳定
但带负载后长期保持小的稳态误差
```

### 36.5 Ki 可能过大

```text
误差过零后仍持续过冲
低频来回摆动
负载解除后恢复很慢
```

### 36.6 Kff 可能过小

```text
启动主要依赖P/I
跟随目标慢
积分需要累积较多
```

### 36.7 Kff 可能过大

```text
目标一出现实测就明显冲过目标
PI长期用负修正抵消前馈
```

### 36.8 死区可能过小

```text
很小目标时PWM增加但轮子不动
积分快速积累后突然起转
```

### 36.9 死区可能过大

```text
低速命令刚出现，轮子就突然跳动
低速难以平滑控制
```

## 37. 推荐调参顺序

调参必须车轮架空开始，并准备随时失能。推荐思路：

### 第一步：先确认非控制参数

确认：

- 左右编码器向前均为正；
- 左右正 PWM 都让车轮向前；
- 轮径正确；
- 每圈计数正确；
- 控制周期稳定；
- 电池电压正常；
- 没有重复 ROS 节点。

### 第二步：确定正反死区

用很低、逐步增加的输出确定每侧每个方向刚能稳定转动的 PWM。不要一开始就调 PI 来掩盖方向或死区问题。

### 第三步：估计 Kff

在若干稳定速度点记录维持速度所需 PWM，拟合近似关系：

```text
PWM ≈ Kff × speed + deadzone
```

正反方向或左右轮差异明显时，应分别设置。

### 第四步：先调 Kp

保持 Ki 较小或暂时为 0，从较小 Kp 开始逐步增加，观察跟随速度和振荡。

### 第五步：加入 Ki

只增加到足以消除长期小偏差，不追求用大 Ki 获得快速响应。快速响应主要由前馈和 P 提供。

### 第六步：检查滤波与斜坡

确认编码器噪声不会让 PWM 抖动，同时滤波延迟没有大到导致振荡。根据机械冲击调整加减速斜率。

### 第七步：分别测试

- 左轮和右轮；
- 正转和反转；
- 低速和中速；
- 架空和落地；
- 空载和正常载重；
- 启动、停车和换向。

每次只改一个参数，并记录修改前后数据。

## 39. 代码设计中值得学习的点

### 39.1 状态与参数分离

`wheel_controller_t` 保存运行状态，`wheel_control_params_t` 保存可配置参数。这样参数可以共享、修改和保存，而运行状态不会被误写入 Flash。

### 39.2 单轮算法与硬件分离

控制器输入、输出都使用物理量和 PWM 数字，不直接访问 TIM 寄存器。因此算法可以在 PC 单元测试中运行，也便于更换硬件接口。

### 39.3 安全许可作为单一入口

复杂故障由上层状态机汇总成 `allow_output`，单轮模块只需保证 0 时清状态并返回零。

### 39.4 使用真实 dt

斜坡和积分使用真实周期，且上层对异常周期做保护，比假设每次绝对等于 10 ms 更可靠。

### 39.5 有前馈的 PI

前馈承担大部分基础输出，PI 修正模型误差，通常比完全依赖积分更容易得到平滑响应。

### 39.6 条件积分抗饱和

用很少的计算避免典型积分 windup，适合 STM32 实时控制。

## 40. 当前实现的边界与可改进方向

### 40.1 没有 D 项

当前是前馈 + PI，不是完整 PID。这不是错误。速度编码器噪声会被 D 项放大，当前通过低通和斜坡获得较容易调试的结构。

### 40.2 低通 α 与采样周期绑定

当前使用固定 α。如果控制周期明显改变，相同 α 对应的实际截止频率也改变。更通用的做法可以根据期望时间常数和 dt 动态计算 α。

### 40.3 死区是阶跃补偿

目标只要略大于零就一次加入全部死区，极低速可能有跳变。以后可以尝试平滑死区补偿，但必须保证仍能可靠起转。

### 40.4 调试量不够完整

当前 `/motor/debug` 没有分别上传前馈、P、I 和原始轮速。若做系统化调参，可以增加这些观测量。

### 40.5 没有电流环

当前最内层直接是 PWM，反馈只有轮速。工业伺服常使用电流环、速度环、位置环多级结构。当前硬件未提供每个电机的快速电流反馈，因此实现的是单速度环。

### 40.6 参数默认值不是最终标定结论

代码注释明确说明默认值用于安全架空验证。是否适合实际载重和落地运动，必须通过实车数据确认。

## 41. 最后用伪代码概括整个函数

```text
函数 update(状态, 单轮参数, 全车参数, 目标, 实测, dt, 允许输出):

    如果指针无效或dt无效:
        返回0

    滤波实测速度

    如果不允许输出:
        清斜坡、积分、误差和PWM
        返回0

    限制最终目标速度
    让斜坡目标按加减速度接近最终目标

    如果最终目标和斜坡目标都已接近0:
        清积分和PWM
        返回0

    根据斜坡目标方向选择正/反死区
    error = 斜坡目标 - 滤波实测
    feedforward = Kff×斜坡目标 + 死区
    P = Kp×error
    I候选 = 旧I + Ki×error×dt

    使用I候选计算一次原始输出并限幅

    如果未饱和，或者误差有助于退出饱和:
        接受I候选
    否则:
        保持旧I

    使用实际接受的I重新计算并限幅
    保存误差
    将浮点PWM四舍五入为int16
    返回PWM
```

## 42. 你现在应当掌握的核心结论

1. 单轮控制器控制的是“轮速”，输入单位 m/s，输出是有符号 PWM；
2. 编码器反馈使它成为闭环，而前馈本身不是闭环；
3. PI 真正跟踪的是斜坡目标和滤波实测，不是原始命令和原始编码器速度；
4. 前馈和死区给出基础输出，P 纠正当前误差，I 消除持续误差；
5. 限幅保护硬件，条件积分防止饱和后积累巨大历史输出；
6. `allow_output=0` 时立即返回零，并清理斜坡和积分；
7. 编码器尖峰检查、状态机、堵转保护和最终 PWM 写寄存器位于其他模块；
8. 左右轮算法相同，但拥有独立状态和可独立标定的参数；
9. 调 PI 之前必须先确认编码器方向、PWM方向、轮径、每圈计数和死区；
10. 当前默认参数是安全验证起点，不等于已经完成所有落地工况的最优标定。
