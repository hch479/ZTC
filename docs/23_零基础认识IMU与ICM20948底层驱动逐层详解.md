## 2. 先不要看代码：IMU 到底是什么

IMU 是英文 `Inertial Measurement Unit` 的缩写，中文通常叫“惯性测量单元”。

它不是一个能直接告诉你“小车位于房间坐标 `(2.3, 1.5)`”的定位器。它更像是小车身体内部的感觉器官，用来感受：

- 自己有没有加速；
- 自己正在绕哪个方向旋转；
- 有些 IMU 还可以感受地磁方向。

ICM20948 内部包含三类传感器：

| 内部传感器 | 轴数 | 主要测量内容 |
|---|---:|---|
| 加速度计 | 3 | x、y、z 三个方向的线加速度/比力 |
| 陀螺仪 | 3 | 绕 x、y、z 三个轴的角速度 |
| 磁力计 AK09916 | 3 | x、y、z 三个方向的地磁场 |

所以厂家把它称为“九轴 IMU”：

```text
3 轴加速度 + 3 轴陀螺仪 + 3 轴磁力计 = 9 轴
```

但是“芯片具有九轴”不等于“当前程序已经使用九轴”。当前项目实际读取和上传的是：

```text
3 轴加速度 + 3 轴陀螺仪 = 6 轴
```

磁力计虽然在原厂初始化代码中被检测和配置，但当前运行任务没有读取磁力计，ROS 消息和里程计融合也没有使用磁力计。

## 3. 什么是 x、y、z 三个轴

先把小车想象成坐在一个三维坐标系中心。

ROS 对车体坐标通常约定：

```text
x 轴：车头向前
y 轴：车体向左
z 轴：车体向上
```

可以想象成：

```text
             z（向上）
             ↑
             │
             │
 y（向左） ← 小车 → 不是一个新轴
            车头
             ↓
        图示方向有限，实际 x 指向车头前方
```

更准确地说：

```text
x：前后方向
y：左右方向
z：上下方向
```

ICM20948 芯片自己也有 x/y/z 方向，但芯片在 PCB 上怎样旋转安装，会决定“芯片 x”是否等于“车体 x”。因此后面的上位机代码提供了轴交换和取反参数。

在底层驱动阶段，我们先忠实读取“芯片原始 x/y/z”，不急着把它改成 ROS 方向。

## 4. 加速度计测的是什么

## 4.1 先理解速度和加速度

速度描述：

```text
物体每秒移动多远、朝哪个方向移动
```

例如：

```text
小车速度 = 0.5 m/s
```

表示每秒前进 0.5 米。

加速度描述：

```text
速度每秒变化多少
```

例如：

```text
加速度 = 1 m/s²
```

可以粗略理解为：每过 1 秒，速度增加 `1 m/s`。

## 4.2 三轴加速度

加速度计分别给出：

```text
ax：x 方向加速度
ay：y 方向加速度
az：z 方向加速度
```

例如小车突然向前加速，车体 x 轴上的加速度读数会明显变化；小车左右振动，y 轴会变化；上下颠簸，z 轴会变化。

## 4.3 为什么静止时还有约 1g

初学者最容易产生疑问：

> 小车明明静止，没有加速，为什么 z 轴不是 0？

因为加速度计会反映重力与支撑产生的“比力”。水平静止放在桌面时，当前项目的坐标和校准方式会让竖直轴保留约：

```text
1 g ≈ 9.80665 m/s²
```

所以一个理想的水平静止结果大致是：

```text
ax ≈ 0
ay ≈ 0
az ≈ +9.80665 m/s²
```

具体正负取决于传感器安装方向和坐标配置。

这也是为什么不能简单地认为：

```text
加速度计非零 = 小车一定在移动
```

它可能只是测到了重力投影。

## 4.4 倾斜时会发生什么

如果把小车向一侧倾斜，重力会同时投影到多个传感器轴：

```text
原本主要在 z 轴的 1g
       ↓ 倾斜
分散到 x/z 或 y/z
```

因此加速度计可以辅助估计俯仰角和横滚角，但前提是小车没有很强的运动加速度。否则“重力”和“车辆运动”会混在一起。

## 5. 陀螺仪测的是什么

## 5.1 角度和角速度不是一回事

角度描述已经转了多少：

```text
向左转了 30°
```

角速度描述转得有多快：

```text
每秒向左转 20°
```

ICM20948 陀螺仪直接给的是角速度，不是角度。

三轴角速度通常写成：

```text
gx：绕 x 轴旋转的角速度
gy：绕 y 轴旋转的角速度
gz：绕 z 轴旋转的角速度
```

对于在水平地面行驶的小车，最常用的是：

```text
gz：绕竖直 z 轴左转/右转的角速度
```

## 5.2 角速度如何变成角度变化

如果 0.05 秒内角速度近似不变：

```text
角度变化 = 角速度 × 时间
```

例如：

```text
角速度 = 0.4 rad/s
时间 = 0.05 s
角度变化 = 0.4 × 0.05 = 0.02 rad
```

这个“乘时间”的过程就是离散积分的最简单形式。

## 5.3 为什么陀螺仪会漂移

理想情况下，小车静止时角速度应该为 0。但真实传感器可能读到：

```text
0.003 rad/s
```

这个很小的固定误差叫零偏。

如果不断积分：

```text
虚假角度 = 0.003 × 时间
```

100 秒后就会积累成：

```text
0.3 rad ≈ 17.2°
```

所以陀螺仪短时间转向响应好，但单独长时间积分会漂移。这正是后面要与编码器组合使用的原因之一。

## 6. 噪声、零偏、漂移分别是什么

这三个词很容易混淆。

## 6.1 噪声

小车完全不动，连续读数可能是：

```text
2, -1, 3, 0, -2, 1 ...
```

这种围绕平均值快速随机变化的部分叫噪声。

常见处理：

- 低通滤波；
- 多点平均；
- 合理机械减振。

## 6.2 零偏

小车静止时，陀螺仪长期平均值可能不是 0，而是 15 个原始计数：

```text
平均值 = 15 LSB
```

这 15 就是零偏。常见处理是开机静止采样并减去平均值。

## 6.3 漂移

零偏和噪声经过积分，会让估计角度随时间逐渐离开真实角度，这种现象通常称为漂移。

温度变化也会让零偏改变，所以一次开机校准不能解决所有温漂问题。

## 7. 原始计数、LSB 和物理单位

ICM20948 寄存器不会直接给出：

```text
9.80665 m/s²
```

它给出的是 16 位有符号整数，例如：

```text
16384
-120
655
```

这些整数叫原始计数，也常用 LSB 表示一个最小数字单位。

当前工程配置：

| 传感器 | 量程 | 灵敏度 |
|---|---|---|
| 加速度计 | ±2g | `16384 LSB/g` |
| 陀螺仪 | ±500°/s | `65.5 LSB/(°/s)` |

所以：

```text
加速度 g = 原始计数 ÷ 16384
角速度 °/s = 原始计数 ÷ 65.5
```

例 1：

```text
加速度原始值 = 16384
16384 ÷ 16384 = 1g
1g = 9.80665 m/s²
```

例 2：

```text
陀螺仪原始值 = 655
655 ÷ 65.5 = 10°/s
10°/s = 10 × π ÷ 180 ≈ 0.17453 rad/s
```

为什么底层不立刻换算成浮点数：

- 底层读取只需要保存真实原始数据；
- 整数通信更紧凑；
- 上位机知道量程后可以统一换算；
- MCU 高频任务减少浮点工作。

## 8. ICM20948 底层代码分成哪些文件

当前相关文件：

```text
HARDWARE/ICM20948/ICM20948.h
HARDWARE/ICM20948/ICM20948.c
HARDWARE/I2C.h
HARDWARE/I2C.c
BALANCE/system.c
```

它们的职责不同：

| 文件 | 作用 |
|---|---|
| `ICM20948.h` | 地址、寄存器、常量、数据类型和函数声明 |
| `ICM20948.c` | 初始化芯片、读取寄存器、滤波、底层偏置 |

| `imu_task.c` | 周期调用驱动、完成项目级校准和发布快照 |

## 9. 怎样阅读 `ICM20948.h`

头文件不是“执行流程”，它更像一张词典：

- 这个芯片地址是多少；
- 某个寄存器叫什么、地址是多少；
- 某一位代表什么配置；
- 数据结构长什么样；
- 哪些函数可以被其他 C 文件调用。

## 9.1 头文件保护

```c
#ifndef __ICM_20948_H
#define __ICM_20948_H
...
#endif
```

作用：防止同一个头文件被重复包含后重复定义。

## 9.2 包含其他头文件

```c
#include "sys.h"
#include "Public_StdTypes.h"
#include "I2C.h"
```

这些文件提供：

- STM32 基础类型和寄存器；
- `uint8_t`、`int16_t` 等整数类型；
- `I2C_ReadOneByte()`、`I2C_WriteOneByte()` 声明。

## 10. I²C 地址为什么是 `0xD0`

头文件定义：

```c
#define I2C_ADD_ICM20948 0xD0
```

ICM20948 常见 7 位地址是 `0x68`。当前厂家 I²C 驱动使用“左移后再留出读写位”的写法：

```text
0x68 左移 1 位 = 0xD0
```

最低位用于表示方向：

```text
最低位 0：写
最低位 1：读
```

所以 `I2C.c` 会执行：

```c
DevAddr | I2C_Direction_Transmitter
DevAddr | I2C_Direction_Receiver
```

在这个工程里，调用者应传 `0xD0`，不能再自行左移。

磁力计地址：

```c
#define I2C_ADD_ICM20948_AK09916 0x0C
```

AK09916 不是直接接到 STM32 的同一条外部访问逻辑中，而是通过 ICM20948 内部 I²C Master 访问，后面会看到 Bank 3 相关寄存器。

## 11. 什么是寄存器

可以把芯片想象成一个有很多编号小抽屉的设备：

```text
0x00 抽屉：可能存器件身份
0x2D 抽屉：可能存加速度 x 高字节
0x2E 抽屉：可能存加速度 x 低字节
```

程序通过 I²C 告诉芯片：

```text
我要读取编号 0x2D 的抽屉
```

芯片返回一个字节。

有些寄存器用来读数据，有些寄存器用来写配置。

例如：

```text
WHO_AM_I：只关心读，确认芯片是谁
GYRO_CONFIG_1：写量程和滤波配置
GYRO_ZOUT_H/L：读 z 轴角速度高低字节
```

---

## 12. 为什么 ICM20948 有多个 Bank

一个字节的寄存器地址只有 0～255。芯片功能很多，为了容纳更多寄存器，ICM20948 使用 Bank 分组。

可以想象成：

```text
Bank 0 的 0x01
Bank 2 的 0x01
Bank 3 的 0x01
```

虽然抽屉编号都叫 `0x01`，但位于不同柜子，含义完全不同。

选择 Bank 的寄存器：

```c
#define REG_ADD_REG_BANK_SEL 0x7F
```

选择值：

```c
#define REG_VAL_REG_BANK_0 0x00
#define REG_VAL_REG_BANK_1 0x10
#define REG_VAL_REG_BANK_2 0x20
#define REG_VAL_REG_BANK_3 0x30
```

例如切换到 Bank 2：

```c
I2C_WriteOneByte(I2C_ADD_ICM20948,
                 REG_ADD_REG_BANK_SEL,
                 REG_VAL_REG_BANK_2);
```

如果忘记切 Bank，就可能把配置写到完全不同的寄存器。

## 14. Bank 2 中当前最重要的配置

## 14.1 陀螺仪量程

头文件提供四种量程位：

```c
REG_VAL_BIT_GYRO_FS_250DPS
REG_VAL_BIT_GYRO_FS_500DPS
REG_VAL_BIT_GYRO_FS_1000DPS
REG_VAL_BIT_GYRO_FS_2000DPS
```

量程越大，能测的最大角速度越高，但每一个计数代表的角速度也更大，低速分辨能力相对下降。

当前选择：

```c
REG_VAL_BIT_GYRO_FS_500DPS
```

即 ±500°/s。

## 14.2 加速度量程

```c
REG_VAL_BIT_ACCEL_FS_2g
REG_VAL_BIT_ACCEL_FS_4g
REG_VAL_BIT_ACCEL_FS_8g
REG_VAL_BIT_ACCEL_FS_16g
```

当前选择：

```c
REG_VAL_BIT_ACCEL_FS_2g
```

小车正常地面运动通常不需要很大 g 值，±2g 能提供较好的分辨率。

## 14.3 DLPF

DLPF 是数字低通滤波器。低通的直观含义是：

```text
保留变化较慢的真实运动趋势
削弱变化很快的高频噪声
```

当前配置把 `DLPCFG_6` 与 DLPF 使能位组合写入配置寄存器。

写法中的 `|` 是按位或：

```c
滤波配置位 | 量程配置位 | 滤波使能位
```

把互不重叠的多个配置位拼成一个字节。

## 15. Bank 3 是做什么的

Bank 3 主要用于 ICM20948 内部 I²C Master。它负责让 ICM20948 自己去访问内部连接的 AK09916 磁力计。

相关寄存器：

```c
I2C_SLV0_ADDR
I2C_SLV0_REG
I2C_SLV0_CTRL
I2C_SLV1_ADDR
I2C_SLV1_REG
I2C_SLV1_CTRL
```

`invmsICM20948ReadSecondary()` 和 `invmsICM20948WriteSecondary()` 会：

1. 切换 Bank 3；
2. 配置内部从设备地址和寄存器；
3. 回到 Bank 0；
4. 启动内部 I²C Master；
5. 从外部传感器数据区取得结果。

当前项目只在初始化阶段检查并配置磁力计，实时任务没有使用磁力计结果。因此初学阶段先理解加速度和陀螺仪即可。

## 16. `ICM20948.h` 中的结构体

## 16.1 三轴传感器数据

```c
typedef struct
{
    int16_t s16X;
    int16_t s16Y;
    int16_t s16Z;
} ICM20948_ST_SENSOR_DATA;
```

它把三个相关变量放在一起：

```text
s16：有符号 16 位
X/Y/Z：三个轴
```

当前用它保存原厂陀螺仪偏置：

```c
ICM20948_ST_SENSOR_DATA gstGyroOffset;
```

## 16.2 8 点平均缓冲区

```c
typedef struct
{
    uint8_t u8Index;
    int16_t s16AvgBuffer[8];
} ICM20948_ST_AVG_DATA;
```

其中：

- `u8Index`：下一次写数组哪个位置；
- `s16AvgBuffer[8]`：保存最近 8 个样本。

每个轴各有一份这种结构。

头文件对外声明：

```c
void invMSInit(void);
u8 ICM20948_Get_Gyroscope(void);
```

其他 C 文件可以调用它们。

`ICM20948.c` 中很多函数带 `static`：


`static` 在这里表示这些函数只供 `ICM20948.c` 内部使用，不对整个工程暴露。

## 18. 软件 I²C 底层怎样工作

当前不是使用 STM32 硬件 I²C 外设，而是软件改变 GPIO 电平模拟 I²C。

引脚：

```c
PB10 → SCL 时钟
PB11 → SDA 数据
```

## 18.1 START

I²C 规定，在 SCL 为高时，SDA 从高变低表示开始：

```text
SCL: ───────── 高 ───────
SDA: 高 ─────→ 低
```

由 `I2C_Start()` 产生。

## 18.2 STOP

在 SCL 为高时，SDA 从低变高表示结束，由 `I2C_Stop()` 产生。

## 18.3 发送一个字节

`I2C_WriteByte()` 循环 8 次：

1. 取当前最高位；
2. 设置 SDA；
3. 拉高 SCL，让对方读取；
4. 拉低 SCL；
5. 数据左移，准备下一位。

## 18.4 ACK

发送一个字节后，接收方把 SDA 拉低表示“收到”。`I2C_WaiteForAck()` 等待这个低电平。

## 18.5 读取一个寄存器

`I2C_ReadOneByte(DevAddr, RegAddr)` 的总线顺序：

```text
START
发送器件写地址
等待 ACK
发送寄存器地址
等待 ACK
重复 START
发送器件读地址
等待 ACK
读取 1 字节
发送 NACK
STOP
```

为什么先写再读：第一次“写”不是要改变传感器数据，而是告诉芯片接下来要读哪个寄存器。

## 19. 系统如何确认当前是 ICM20948

`systemInit()` 先完成：

```c
I2C_GPIOInit();
```

然后先尝试 MPU6050，再尝试 ICM20948：

```c
if (MPU6050_DEFAULT_ADDRESS == MPU6050_getDeviceID())

    SysVal.HardWare_Ver = V1_0;

}
else if (REG_VAL_WIA == ICM20948_getDeviceID())

else
{

}
```

ICM20948 身份读取函数：

```c
uint8_t ICM20948_getDeviceID(void)
{
    return I2C_ReadOneByte(I2C_ADD_ICM20948, REG_ADD_WIA);
}
```

读到 `0xEA` 后：

```text
SysVal.HardWare_Ver = V1_1
```

后续 `main.c` 就知道应该创建 ICM20948 任务，而不是 MPU6050 任务。

## 20. `invMSInit()` 与完整初始化流程

调用关系：

```text
systemInit()
  └─ invMSInit()
       ├─ invmsICM20948Check()
       └─ invmsICM20948Init()
```

`invmsICM20948Init()` 按顺序做：

### 第一步：Bank 0 复位

```c
选择 Bank 0
写复位值
等待 10 ms
写运行模式
```

### 第二步：Bank 2 配置陀螺仪

```c
GYRO_SMPLRT_DIV = 0x07
GYRO_CONFIG_1 = DLPF配置6 | ±500dps | 开启DLPF
```

### 第三步：配置加速度计

```c
ACCEL_SMPLRT_DIV_2 = 0x07
ACCEL_CONFIG = DLPF配置6 | ±2g | 开启DLPF
```

### 第四步：回 Bank 0

后面的传感器输出寄存器都在 Bank 0。

### 第五步：等待 100 ms

让传感器配置稳定。

### 第六步：原厂陀螺仪偏置

调用 `invmsICM20948GyroOffset()` 读取 32 次静止数据。

### 第七步：检测并配置磁力计

当前只初始化，没有在周期任务里使用磁力计读数。

## 21. 加速度底层读取逐步拆解

调用链：

```text
ICM20948_Get_Accel()
  └─ invMSAccelRead()
       └─ invmsICM20948AccelRead()
```

## 21.1 为什么函数参数是指针

```c
static void invmsICM20948AccelRead(
    int16_t *ps16X,
    int16_t *ps16Y,
    int16_t *ps16Z)
```

函数需要同时返回三个结果，C 函数普通 `return` 只能直接返回一个值，所以传入三个变量的地址。

函数内部：

```c
*ps16X = 结果X;
```

表示把结果写到调用者的 x 变量中。

调用时：

```c
invMSAccelRead(&imu.accel.x,
               &imu.accel.y,
               &imu.accel.z);
```

`&` 表示取得变量地址。

## 21.2 读取高低字节

以 x 轴为例：

```c
u8Buf[0] = I2C_ReadOneByte(..., ACCEL_XOUT_L);
u8Buf[1] = I2C_ReadOneByte(..., ACCEL_XOUT_H);
s16Buf[0] = (u8Buf[1] << 8) | u8Buf[0];
```

假设：

```text
高字节 = 0x3F
低字节 = 0x20
```

高字节左移 8 位：

```text
0x3F → 0x3F00
```

与低字节按位或：

```text
0x3F00 | 0x20 = 0x3F20
```

作为十进制有符号 16 位数就是一个正原始计数。

负数例子：

```text
高字节 = 0xFF
低字节 = 0x9C
组合 = 0xFF9C
作为 int16_t = -100
```

## 21.3 三个轴分别读取

相同步骤重复三次：

```text
XOUT_L/H → s16Buf[0]
YOUT_L/H → s16Buf[1]
ZOUT_L/H → s16Buf[2]
```

## 21.4 8 点平均

每个轴调用：

```c
invmsICM20948CalAvgValue(...)
```

最终：

```c
*ps16X = s32OutBuf[0];
*ps16Y = s32OutBuf[1];
*ps16Z = s32OutBuf[2];
```

写入 `imu.accel.x/y/z`。

## 22. 陀螺仪底层读取逐步拆解

调用链：

```text
ICM20948_Get_Gyroscope()
  └─ invMSGyroRead()
       └─ invmsICM20948GyroRead()
```

寄存器读取、字节组合和加速度相同，只是地址换成 `GYRO_X/Y/ZOUT`。

陀螺仪多一步：减去原厂初始化偏置。

```c
*ps16X = s32OutBuf[0] - gstGyroOffset.s16X;
*ps16Y = s32OutBuf[1] - gstGyroOffset.s16Y;
*ps16Z = s32OutBuf[2] - gstGyroOffset.s16Z;
```

数据流：

```text
寄存器瞬时值
    ↓
8 点平均
    ↓
减去 gstGyroOffset
    ↓
imu.gyro.x/y/z
```

## 23. 8 点滑动平均到底怎样算

函数：

```c
invmsICM20948CalAvgValue()
```

核心步骤：

```c
buffer[index] = new_value;
index++;
index &= 0x07;

sum = buffer[0] + ... + buffer[7];
output = sum >> 3;
```

`index &= 0x07` 会让下标保持在 0～7：

```text
0,1,2,3,4,5,6,7,0,1...
```

这叫循环缓冲区。

`sum >> 3` 对正整数相当于除以 8，因为：

```text
2³ = 8
```

假设最近 8 个值：

```text
100, 102, 98, 101, 99, 103, 97, 100
```

总和：

```text
800
```

平均：

```text
800 ÷ 8 = 100
```

优点：噪声更小。

代价：真实运动变化会被稍微平滑和延迟。

刚开机时数组初始为 0，所以前几个平均值会被零拉低。本项目后续增加 50 个样本预热，正好让这些缓冲区先被真实数据填满再开始长期校准。

## 24. 原厂 32 点陀螺仪偏置

初始化函数调用：

```c
invmsICM20948GyroOffset();
```

它循环 32 次：

```c
for (i = 0; i < 32; i++)
{
    读取 gx、gy、gz;
    累加;
    delay_ms(10);
}
```

最后右移 5 位：

```text
2⁵ = 32
```

也就是除以 32 得平均值。

保存到：

```c
gstGyroOffset.s16X
gstGyroOffset.s16Y
gstGyroOffset.s16Z
```

这是一层快速的底层静止偏置估计。

后续项目级 500 点校准仍然有意义，因为它：

- 等传感器和 8 点缓冲区更稳定；
- 计算完整运行链路剩余的陀螺仪偏置；
- 同时校准加速度三个轴；
- 向上层提供明确的校准进度和完成标志。

## 25. `ICM20948_Get_Accel()` 在做什么

它先把底层结果写入：

```c
imu.accel.x
imu.accel.y
imu.accel.z
```

然后看：

```c
SysVal.Time_count < CONTROL_DELAY
```

如果还在校准阶段，保留当前原始/初步滤波计数。

校准完成后：

```c
imu.Original_accel = 当前读数;

imu.accel.x = Original.x - Deviation.x;
imu.accel.y = Original.y - Deviation.y;
imu.accel.z = Original.z - Deviation.z + 16384;
```

前两个轴静止目标接近 0；z 轴重新加 16384，让水平静止时保留约 `+1g`。

这里的 `Deviation_accel` 由上层 IMU 任务的 500 点静止平均生成，下一份文档详细讲。

---

## 26. `ICM20948_Get_Gyroscope()` 在做什么

底层 `invMSGyroRead()` 已经做过：

```text
寄存器读取 → 8点平均 → 减 gstGyroOffset
```

公共函数再根据项目校准状态做：

```c
imu.Original_gyro = 当前读数;
imu.gyro = Original_gyro - Deviation_gyro;
```

所以完整陀螺仪路径中有两级偏置处理：

```text
第一级：ICM20948.c 初始化时 32 点 gstGyroOffset
第二级：imu_task.c 稳定后 500 点 Deviation_gyro
```

第二级主要消除第一级之后残留的平均偏差。

## 27. `IMU_DATA_t imu` 是整个底层数据中心

结构体定义在 `imu_task.h`，全局变量定义在 `imu_task.c`：

```c
IMU_DATA_t imu;
```

内部包含：

| 字段 | 意义 |
|---|---|
| `Deviation_accel` | 项目静止校准得到的加速度平均偏置 |
| `Deviation_gyro` | 项目静止校准得到的陀螺仪剩余偏置 |
| `Original_accel` | 校准完成后的本次原始加速度计数 |
| `Original_gyro` | 校准完成后的本次原始角速度计数 |
| `accel` | 最终给上层使用的校正后加速度计数 |
| `gyro` | 最终给上层使用的校正后角速度计数 |

注意：这里仍然是计数，还没换算成 `m/s²` 和 `rad/s`。

## 30. 当前底层驱动值得注意的实现细节

这些不影响你先学习和使用，但理解后有助于将来优化。

## 30.1 每个字节单独读取

当前一个三轴传感器要分别进行 6 次单字节 I²C 事务。

优点：代码简单。

可优化点：将连续寄存器一次 burst read，可减少总线开销，并降低高低字节跨采样更新的概率。

## 30.2 ACK 结果没有层层上报

`I2C_WaiteForAck()` 能判断超时，但上层 `I2C_ReadOneByte()` 没有把所有失败状态完整传播到 IMU 状态。

当前传感器完全不响应时，系统启动阶段通常会因为 WHO_AM_I 错误而复位；运行中的短时 I²C 故障缺少独立计数和故障帧。

后续可以增加：

- 连续 I²C 错误计数；
- IMU fault 状态；
- 超过阈值停止融合。

当前 RDK 已经有“数据超时后停止融合”的第二层保护。

## 30.3 两个公共读取函数的返回值

原厂 `ICM20948_Get_Accel()` 和 `ICM20948_Get_Gyroscope()` 声明返回 `u8`，内部局部变量 `res` 没有真正赋值，但当前调用者也没有使用返回值。

更规范的后续改法是：

- 如果不需要状态，改为 `void`；
- 如果需要状态，让底层 I²C 明确返回成功/失败并逐层传递。

本次为了减少对已经验证过的原厂底层驱动的改动，没有在接入时大范围重写它。

## 30.4 温度补偿尚未实现

ICM20948 零偏会随温度变化。当前是开机静止校准，没有建立“温度—零偏”曲线。

对于当前教育小车和短时间测试可以先接受；如果以后做长时间高精度航向，需要考虑在线零偏估计或温度补偿。

## 32. 建议做的四个零基础实验

## 实验一：静止数据

## 实验二：只向前后倾斜

## 实验四：校准期间故意移动与正确静止对比

## 33. 从寄存器到全局变量的完整路径

以 z 轴陀螺仪为例：

```text
ICM20948 内部真实角速度
    ↓ 模拟与数字转换
GYRO_ZOUT_H / GYRO_ZOUT_L
    ↓ I2C_ReadOneByte()
两个 uint8_t
    ↓ (high << 8) | low
一个 int16_t 原始计数
    ↓ 8 点滑动平均
平滑计数
    ↓ 减 gstGyroOffset.s16Z
第一层校正计数
    ↓ 写 imu.gyro.z
项目 IMU 任务取得当前数据
    ↓ 校准完成后减 Deviation_gyro.z
最终校正计数
```

到这里仍然没有 ROS，也没有里程计。下一份文档将从这个“最终校正计数”继续向上追踪。

## 34. 本文最重要的十句话

1. IMU 不直接给位置，它给加速度、角速度以及可选磁场。
2. 当前项目只使用 ICM20948 的加速度计和陀螺仪，即六轴。
3. 水平静止时，加速度竖直轴约为 1g 是正常现象。
4. 陀螺仪给角速度，乘以时间才得到角度变化。
5. 小零偏长期积分会造成明显航向漂移。
6. 当前加速度量程是 ±2g，陀螺仪量程是 ±500°/s。
7. ICM20948 使用寄存器 Bank，读写前必须位于正确 Bank。
8. 每个轴由高低两个字节组合成一个 `int16_t`。
9. 原厂底层做 8 点平均和 32 点陀螺仪偏置，项目任务又做更稳定的 500 点校准。
10. 底层结束时得到的仍是校正计数；单位换算、ROS 和里程计融合属于上层应用。
