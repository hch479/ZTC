# 目标加减速度为什么可以固定，以及一次完整闭环控制怎样算

## 1. 先直接回答：`0.50` 和 `0.80` 是怎样得到的

当前代码中的：

```c
params->acceleration_mps2 = 0.50f;
params->deceleration_mps2 = 0.80f;
```

不是根据某个 PWM 数值计算出来的，也不是程序自动辨识出来的电机物理参数。

它们是写入 `chassis_params_set_defaults()` 的一组**保守初始设定值**，用于限制“控制器内部目标轮速”改变得太快。在没有对这辆车进行实测标定以前，这两个值不能称为最终准确参数。

你的疑问是合理的：

> 不同 PWM、电池电压、当前转速、车重、坡度和地面摩擦下，真实加速度确实不同。

但是这与代码中的 `acceleration_mps2` 不是同一个概念。必须先把下面两种加速度彻底分开。

---

## 2. “目标加速度”和“真实加速度”不是一回事

### 2.1 代码中的目标加速度

`approach_target()` 限制的是：

```text
斜坡目标速度每秒最多变化多少 m/s
```

用公式表示：

```text
目标加速阶段：r[k] - r[k-1] ≤ acceleration × dt
目标减速阶段：|r[k] - r[k-1]| ≤ deceleration × dt
```

其中 `r[k]` 是控制器本周期使用的目标速度，不是真实轮速。

默认值 `acceleration=0.50 m/s²`、`dt=0.01 s` 时：

```text
每个 10 ms 周期，目标最多增加 0.50×0.01=0.005 m/s
```

所以当上位机突然要求 `0.05 m/s` 时，控制器看到的是：

```text
0.005 → 0.010 → 0.015 → ... → 0.050 m/s
```

它的作用类似于告诉驾驶员：

```text
油门踏板不要瞬间踩到底，要按照规定速度逐渐踩下去。
```

但它不能保证汽车真实速度恰好按照这个斜率上升。

### 2.2 编码器测到的真实加速度

真实轮速记为 `v[k]`，可以近似估算真实加速度：

```text
a_real[k] ≈ (v[k] - v[k-1]) / dt
```

例如：

```text
上周期真实轮速 = 0.020 m/s
本周期真实轮速 = 0.024 m/s
dt = 0.01 s
```

则估算的真实加速度为：

```text
(0.024-0.020)/0.01 = 0.40 m/s²
```

下一个周期如果只从 `0.024` 增加到 `0.026`，真实加速度就变为：

```text
(0.026-0.024)/0.01 = 0.20 m/s²
```

所以真实加速度当然会变化。

### 2.3 两者在闭环里怎样配合

```text
上位机最终目标速度
        ↓
固定的目标加速度限制
        ↓
得到平滑的斜坡目标 r[k]
        ↓                         ┌──────────────┐
与编码器真实轮速比较 ────────────←│ 电机真实响应 │
        ↓                         └──────────────┘
PI 根据误差增减 PWM
```

如果真实电机加速不够快：

```text
真实速度 < 斜坡目标
→ 误差为正
→ P、I 输出增加
→ PWM 增加
```

如果真实电机比目标升得太快：

```text
真实速度 > 斜坡目标
→ 误差变小甚至为负
→ P、I 输出降低
→ PWM 减小
```

因此固定的是“目标变化上限”，真正的 PWM 仍然由每个周期的编码器反馈动态决定。

## 3. 为什么 PWM 与真实加速度不是固定一一对应

直流电机更接近下面的物理关系：

```text
PWM占空比 × 电池电压
        ↓
电机平均端电压
        ↓  还要减去转速产生的反电动势
电枢电流
        ↓
电机转矩
        ↓  再减去负载、摩擦、坡度等阻力
车轮角加速度和整车加速度
```

用简化公式表示：

```text
电机平均电压 Vmotor ≈ duty × Vbattery
电流 i ≈ (Vmotor - Ke×ω) / R
电机转矩 Tmotor ≈ Kt×i
真实加速度 a ≈ (驱动力 - 阻力) / 质量
```

同样是 PWM 3000，可能出现不同加速度：

- 电池 12.6 V 时比 10.6 V 时电机端电压高；
- 低速时反电动势小，高速时反电动势大；
- 车轮架空时负载小，落地载物时负载大；
- 上坡需要克服重力，下坡可能反而被重力推动；
- 静止起步要先克服静摩擦，转动以后主要是动摩擦；
- 轮胎打滑时，电机转速增加却不代表车体得到相同加速度。

因此不能建立一个简单规则：

```text
PWM 1000 = 0.1 m/s²
PWM 2000 = 0.2 m/s²
```

这种规则只有在电压、速度、负载、地面等条件都近似固定时，才可能作为局部经验模型。

## 4. 固定目标加速度限制是否合理

### 4.1 对当前项目是合理的第一版设计

“轨迹斜坡 + 内部速度闭环”是常见的分层方式：

```text
轨迹层：规定目标速度最多变化多快
速度环：努力让真实轮速跟随这个目标
```

固定加速度限制的优点是：

- 代码简单，容易验证；
- 避免 `/cmd_vel` 突变直接制造 PWM 冲击；
- 减少起步打滑和机械冲击；
- 不依赖精确的电机模型；
- 上位机参数容易理解和调整。

### 4.2 固定值并不保证在所有工况下都能跟上

若目标加速度设为 `2.0 m/s²`，但满载小车在高转速时只能做到 `0.6 m/s²`，那么：

```text
斜坡目标会上升得比真实轮速快
→ 误差持续增加
→ PWM 可能达到上限
→ 实际加速度仍只能由硬件能力决定
```

代码有 PWM 限幅和条件积分抗饱和，因此不会因为目标不可实现就无限增加积分，但速度跟踪会落后。

### 4.3 什么情况下值得进一步改进

如果以后实测发现：

- 低速轻载能轻松跟上，高速满载明显跟不上；
- 电池电压下降后跟踪性能差别很大；
- 加速时轮胎打滑；
- 需要严格限制电流或牵引力；
- 需要准确复现某条速度曲线；

可以考虑：

1. 按当前速度分段设置目标加速度；
2. 根据电池电压降低高速加速度要求；
3. 加入电机电流检测，用转矩/电流作为更底层的限制；
4. 在现有速度前馈上增加加速度前馈项：

```text
PWM前馈 = Ks×sign(r) + Kv×r + Ka×a_ref
```

当前代码只有近似的：

```text
死区 Ks + 速度前馈 Kv×r
```

还没有 `Ka×a_ref`。

不要简单地让目标加速度直接跟随当前 PWM 变化。PWM 本身已经是闭环根据误差算出的结果，再用它反过来决定目标变化率，容易形成不清楚的相互作用。更稳妥的升级方向是根据实测硬件能力、速度、电压和电流制定调度规则。

## 5. 当前 `0.50`、`0.80` 应该怎样实测确定

当前数值只是初值，最终建议按下面方法标定。

### 5.1 先确定希望限制什么

需要考虑：

- 起步是否打滑；
- 车上设备能否承受冲击；
- 电机峰值电流是否过大；
- 满载时能否跟上目标斜坡；
- 正常停车距离是否合适；
- 地面附着条件是否稳定。

目标加速度不是越大越好，而是在响应速度、平顺性、电流和附着力之间取舍。

### 5.2 通过编码器记录实际响应

在安全场地，以较小目标速度开始测试，记录：

```text
时间戳
ramped_target_mps
raw_speed_mps
filtered_speed_mps
output_pwm
电池电压
```

不要直接用相邻两个噪声较大的原始速度算加速度。可以用较长窗口，例如 50 ms：

```text
a_real ≈ (v[k] - v[k-5]) / 0.05
```

这样比：

```text
(v[k] - v[k-1]) / 0.01
```

更不容易被编码器量化噪声放大。

### 5.3 选择可重复实现的值

例如多次测试得到：

```text
轻载可重复达到 1.0 m/s²
满载、低电压时只能稳定达到 0.65 m/s²
```

那么正常运行目标加速度可以先选择比最差工况能力更低的值，例如：

```text
0.4～0.5 m/s²
```

再观察跟踪误差、电流、打滑和机械冲击。

默认 `0.50 m/s²` 就是这种偏保守的起点，但目前没有实车试验数据证明它是最佳值。

### 5.4 为什么减速度默认比加速度大

当前设置：

```text
正常加速 0.50 m/s²
正常减速 0.80 m/s²
```

意图是让起步较平缓、正常停车更干脆。但 `0.80` 同样需要实车验证：太大可能打滑或产生明显点头，太小则停车距离较长。

这里的减速度只用于正常减速和换向。急停、严重故障或禁止输出时，安全状态机会直接令 PWM 为零，不等待普通减速度斜坡慢慢走完。

## 6. 开始完整算例前，先说明当前代码并不是完整 PID

用户经常把电机闭环统称为 PID，但当前实际公式是：

```text
PWM = 死区补偿 + 速度前馈 + P + I
```

即：

```text
u = deadzone + Kff×r + Kp×(r-y) + integral
```

积分更新为：

```text
integral[k] = integral[k-1] + Ki×error[k]×dt
```

当前没有：

```text
Kd × (error[k]-error[k-1])/dt
```

所以严格来说这是“前馈 + 死区补偿 + PI”，不是完整的 P+I+D。

对编码器低速量化明显的电机，D 项容易放大测速噪声；第一版不用 D 项是可以理解的选择。

## 7. 完整算例的初始条件

下面只计算左轮，右轮过程相同。

假设上位机运动学计算后，左轮最终目标突然从 0 变为：

```text
target_mps = 0.050 m/s
```

安全状态机允许输出：

```text
allow_output = 1
```

控制周期和参数为：

```text
dt = 0.010 s
acceleration = 0.50 m/s²
deceleration = 0.80 m/s²
alpha = 0.35
Kff = 9000
Kp = 3000
Ki = 1500
dead_forward = 700
output_limit = 16700
wheel_diameter = 0.065 m
counts_per_wheel_rev = 60000
```

控制器刚复位，因此历史状态为：

```text
ramped_target = 0
filtered_speed = 0
integral_output = 0
```

为了展示真实反馈，假设随后 12 个周期读取到的编码器增量是：

```text
0, 12, 35, 62, 88, 112, 129, 141, 147, 150, 151, 149
```

这些编码器数值只是一个合理的演示序列，不是由代码提前预测出来的。真实计数必须由实际电机、负载和编码器产生。

## 8. 第一步：编码器增量怎样变成原始速度

轮子一圈周长：

```text
C = π×D
  = 3.1415926×0.065
  ≈ 0.204204 m
```

一个编码器计数对应的行驶距离：

```text
distance_per_count = 0.204204/60000
                   ≈ 0.0000034034 m
```

在 10 ms 周期内，一个计数对应的速度分辨率：

```text
speed_per_count = 0.0000034034/0.01
                ≈ 0.00034034 m/s
```

第 2 周期编码器增量为 12，原始速度就是：

```text
x[2] = 12×π×0.065/(60000×0.01)
     ≈ 0.004084 m/s
```

注意：原始速度只能以大约 `0.00034034 m/s` 的台阶变化。这就是低速时编码器测速会跳动的一个原因。

---

## 9. 第二步：一阶低通滤波到底在做什么

代码：

```c
filtered += alpha * (raw - filtered);
```

可以用一句话理解：

> 每次只走完“原始测速与旧滤波值之间差距”的 35%。

### 9.1 第 1 周期

```text
原始速度 x[1] = 0
旧滤波值 y[0] = 0
两者差距       = 0-0 = 0
走差距的 35%   = 0.35×0 = 0
新滤波值 y[1] = 0+0 = 0
```

### 9.2 第 2 周期

```text
原始速度 x[2] = 0.004084
旧滤波值 y[1] = 0
两者差距       = 0.004084-0 = 0.004084
走差距的 35%   = 0.35×0.004084 = 0.001429
新滤波值 y[2] = 0+0.001429 = 0.001429 m/s
```

这里没有把滤波值直接改成 `0.004084`，因为编码器这一次的变化可能包含量化跳动或干扰。

### 9.3 第 3 周期

```text
原始速度 x[3] = 0.011912
旧滤波值 y[2] = 0.001429
两者差距       = 0.011912-0.001429 = 0.010483
走差距的 35%   = 0.003669
新滤波值 y[3] = 0.001429+0.003669
              = 0.005098 m/s
```

最关键的是：第 3 周期的旧值是上周期**滤波后的 `0.001429`**，不是上周期原始值 `0.004084`。

### 9.4 为什么它能滤掉一个尖峰

假设稳定时滤波值是 `0.050`，某一次原始测速因干扰突然跳到 `0.100`：

```text
新滤波值 = 0.050 + 0.35×(0.100-0.050)
          = 0.0675
```

原始值跳了 `0.050`，滤波输出只跳了 `0.0175`。如果下一周期原始值恢复 `0.050`：

```text
新滤波值 = 0.0675 + 0.35×(0.050-0.0675)
          = 0.061375
```

之后会逐渐回到 `0.050`。这就是“削弱尖峰”，代价是正常变化也会有延迟。

## 10. 第三步：目标斜坡怎样计算

最终目标是 `0.050 m/s`，但斜坡每周期最多增加 `0.005 m/s`：

```text
r[1] = 0.005
r[2] = 0.010
r[3] = 0.015
...
r[10] = 0.050
r[11] = 0.050
```

低通滤波处理“实测速度”，目标斜坡处理“目标速度”。两者是两条不同的数据线：

```text
编码器原始速度 ──低通滤波──→ y[k]
上位机最终目标 ──目标斜坡──→ r[k]
                              ↓
                       error=r[k]-y[k]
```

## 11. 第四步：把第 2 周期的 PI 和前馈完整算完

第 1 周期已经得到：

```text
旧积分 I[1] = 0.075 PWM
```

第 2 周期的数据为：

```text
斜坡目标 r[2] = 0.010000 m/s
滤波速度 y[2] = 0.001429 m/s
```

### 11.1 误差

```text
error[2] = r[2]-y[2]
         = 0.010000-0.001429
         = 0.008571 m/s
```

### 11.2 正转死区

斜坡目标为正，因此：

```text
deadzone = +700 PWM
```

这个基础值用于帮助克服电机静摩擦和驱动死区。

### 11.3 速度前馈

代码把速度前馈和死区放在同一个 `feedforward` 变量中：

```text
feedforward = Kff×r + deadzone
            = 9000×0.010000 + 700
            = 790 PWM
```

### 11.4 比例项 P

```text
P = Kp×error
  = 3000×0.008571
  ≈ 25.712 PWM
```

### 11.5 积分增量和新积分

```text
ΔI = Ki×error×dt
   = 1500×0.008571×0.01
   ≈ 0.1286 PWM

I[2] = I[1]+ΔI
     = 0.075+0.1286
     ≈ 0.2036 PWM
```

积分数值看起来很小，是因为这里只经过了两个 10 ms 周期。若长期存在同方向误差，它会逐周期积累。

### 11.6 总输出

```text
u = feedforward + P + I
  = 790 + 25.712 + 0.2036
  = 815.916 PWM
```

没有超过 `±16700`，所以没有触发限幅，积分也允许更新。

### 11.7 转换为整数

正数按代码加 `0.5` 后取整数：

```text
815.916 → 816
```

因此第 2 周期左轮控制器返回：

```text
left_pwm = +816
```

- P 项根据当前误差做快速修正；
- I 项目前很小，但会慢慢消除长期残余误差；
- PWM 不是按照固定加速度查表得到的，而是每周期根据反馈重新计算。

---

## 13. 第五步：第 2 周期的 `+816` 怎样进入 H 桥

当前左轮方向符号为：

```c
C30D_LEFT_PWM_SIGN = 1
```

所以传给 `Set_Pwm()` 的 A 电机值仍为：

```text
motor_a = +816
```

`motor_a >= 0`，执行：

```c
PWMA2 = 16799;
PWMA1 = 16799 - motor_a;
```

代入：

```text
PWMA2 = 16799
PWMA1 = 16799-816 = 15983
```

两路 PWM 的差值为 816，有效差分比例近似为：

```text
816/16799 ≈ 4.86%
```

驱动电路根据两路输入形成某一极性的电机端电压。若控制器返回 `-816`，则会交换哪一路保持接近 100%，从而反转差分电压方向。

从上位机目标到硬件寄存器的第 2 周期完整链条为：

```text
上位机最终目标 0.050 m/s
        ↓ 目标加速度限制
本周期斜坡目标 0.010000 m/s
        ↑
编码器增量 12
        ↓ 距离/周期
原始速度 0.004084 m/s
        ↓ alpha=0.35
滤波速度 0.001429 m/s
        ↓
误差 0.008571 m/s
        ↓
前馈含死区 790 + P 25.712 + I 0.2036
        ↓
浮点输出 815.916
        ↓ 四舍五入
有符号 PWM +816
        ↓ Set_Pwm
PWMA2=16799，PWMA1=15983
        ↓
电机驱动 H 桥输出正方向的平均差分电压
```

## 14. 如果目标突然变成零，减速度怎样参与

假设当前斜坡目标已经是：

```text
r = 0.050 m/s
```

上位机把最终目标改为零。默认减速度为 `0.80 m/s²`，每周期最多减少：

```text
0.80×0.01 = 0.008 m/s
```

理论斜坡序列为：

```text
0.050
→ 0.042
→ 0.034
→ 0.026
→ 0.018
→ 0.010
→ 0.002
→ 0
```

在每个周期中，编码器仍会给出真实速度，低通滤波仍会更新，PI 仍根据：

```text
error = 正在下降的斜坡目标 - 滤波速度
```

计算输出。

若真实轮速下降得不够快，误差可能变为负，P 项和积分就会降低 PWM，必要时可能给出反向的制动作用。

当前代码在最终目标接近零且斜坡目标也小于很小阈值时，会直接清积分并输出零，避免静止时仍有电流和啸叫。

## 15. 如果没有低通滤波，同一例子会怎样

假设第 2 周期直接使用原始速度：

```text
error_without_filter = 0.010000-0.004084
                     = 0.005916
```

有滤波时：

```text
error_with_filter = 0.010000-0.001429
                  = 0.008571
```

因为滤波速度对上升过程有滞后，控制器暂时认为电机更慢，从而给出更大的 P 输出。这说明滤波不仅让曲线平滑，也会影响闭环动态。

因此 `alpha` 太小可能造成：

- 测速看起来很平滑；
- 但反馈滞后明显；
- 加速时控制器可能多给 PWM；
- 停车时也可能晚看到速度下降；
- PI 参数需要与滤波强度一起整定。

`alpha` 不能只看测速曲线是否漂亮，还要看真实速度跟踪和是否振荡。

---

## 16. 这个完整例子不能证明什么

本例可以准确展示代码怎样运算，但不能凭空证明某个 PWM 会产生例子中的编码器计数。

原因是：

```text
控制算法可以由输入数据准确算出 PWM；
但要从 PWM 准确预测真实速度，必须有电机、驱动、负载和地面的物理模型。
```

本例的编码器序列是作为“硬件已经测到的反馈输入”提供给算法的。真正标定时，必须用你的小车实测数据替换这组演示数据。

## 17. 最终结论

1. `0.50 m/s²` 和 `0.80 m/s²` 是目标速度斜坡限制的保守初值，不是 PWM 对应的真实加减速度。
2. 不同 PWM 对应的真实加速度确实会变化，而且还受电压、转速、负载、坡度和摩擦影响。
3. 固定目标加速度与动态 PWM 并不矛盾：前者负责生成平滑目标，后者由闭环根据真实反馈不断修正。
4. 一阶低通滤波就是每周期走完“新测量与旧滤波值差距”的 `alpha` 比例；旧值始终是上次滤波结果。
5. 当前控制器严格来说是“死区 + 速度前馈 + PI”，没有 D 项。
6. 当前加减速度参数应通过实车记录目标速度、编码器速度、PWM 和电池电压后重新确认。
7. 若将来需要更高精度，可增加速度/电压调度、电流限制和加速度前馈，而不是简单建立固定的 PWM—加速度表。
