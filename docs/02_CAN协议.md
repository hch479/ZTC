# CAN 协议详细说明

## 1. 总体规则

- 物理速率：`1 Mbit/s`，与资料中的 `CAN1_Mode_Init(1,7,6,3,0)` 一致。
- 帧格式：经典 CAN 2.0A，11 位标准 ID，数据帧，DLC 固定为 8。
- 字节序：小端。
- 速度单位：报文内整数使用 mm/s、mrad/s；程序内部使用 m/s、rad/s。
- 命令、状态、编码器和应答帧的第 7 字节为 CRC8；轮速和 PWM 遥测因 8 字节全部用于测量量，仅使用 CAN 控制器自带链路 CRC。
- 应用 CRC：CRC-8/ATM，poly `0x07`，init `0x00`，不反射，xorout `0x00`，计算字节 0..6。

## 2. 报文列表

| CAN ID | 方向 | 周期/触发 | 内容 |
|---|---|---|---|
| `0x101` | RDK -> STM32 | 20 ms | 运动命令 |
| `0x102` | RDK -> STM32 | 按需 | 参数读写 |
| `0x103` | RDK -> STM32 | 按需 | 清故障、保存参数、清里程计 |
| `0x181` | STM32 -> RDK | 20 ms | 左右目标和实测轮速 |
| `0x182` | STM32 -> RDK | 20 ms | 左右 PWM 和速度误差 |
| `0x183` | STM32 -> RDK | 50 ms | 左编码器 |
| `0x184` | STM32 -> RDK | 50 ms | 右编码器 |
| `0x185` | STM32 -> RDK | 100 ms | 状态和故障 |
| `0x186` | STM32 -> RDK | 应答 | 参数/系统命令结果 |
| `0x700` | STM32 -> RDK | 1 s | 心跳和固件版本 |

总线周期负载很低。按每个经典 CAN 数据帧约 130 bit 粗略估算，正常遥测约 `2*50 + 2*20 + 10 + 1 = 151 frame/s`，约占 1 Mbit/s 总线的 2%。

## 3. `0x101` 运动命令

| 字节 | 类型 | 内容 |
|---|---|---|
| 0..1 | int16 | 线速度，mm/s |
| 2..3 | int16 | 角速度，mrad/s |
| 4 | uint8 | bit0 enable，bit1 estop |
| 5 | uint8 | 协议版本，当前为 1 |
| 6 | uint8 | 滚动序号 |
| 7 | uint8 | CRC8 |

STM32 只把 CRC 正确且版本为 1 的报文当作有效命令。无效帧不会刷新 200 ms 看门狗。

## 4. `0x102` 参数命令

| 字节 | 类型 | 内容 |
|---|---|---|
| 0 | uint8 | 参数 ID |
| 1 | uint8 | 0=读，1=写 |
| 2..5 | IEEE754 float32 | 参数值 |
| 6 | uint8 | 序号 |
| 7 | uint8 | CRC8 |

两端当前都是小端 IEEE754。运行状态禁止改参数。写参数只改变 STM32 RAM；调用保存命令后才擦写内部 Flash。

参数 ID 与 `config/chassis.yaml` 的完整对应见 `can_protocol.py` 中 `PARAMETER_IDS`。重要 ID：

| ID | 参数 |
|---:|---|
| 1/2/3 | 左轮 Kp/Ki/Kff |
| 4/5/6 | 右轮 Kp/Ki/Kff |
| 7..10 | 左右正反转死区 |
| 11/12 | 加速度/减速度 |
| 13 | 速度滤波 alpha |
| 14/15 | 直行同步 Kp/最大修正 |
| 16/17/18 | 轮距/轮径/每圈计数 |
| 19 | 最大线速度 |
| 20/21 | 欠压阈值/命令超时 |
| 22..25 | 堵转条件 |
| 26 | 车体类型：0 差速，1 阿克曼 |
| 27..30 | 轴距、最大转角、舵机中值、舵机比例 |

## 5. `0x103` 系统命令

| 字节 | 内容 |
|---|---|
| 0 | opcode：1 清故障，2 保存参数，3 清里程计 |
| 1 | 固定钥匙 `0xA5` |
| 2 | 固定钥匙 `0x5A` |
| 3 | 序号 |
| 4..6 | 预留，当前为 0 |
| 7 | CRC8 |

钥匙和 CRC 不能代替机械急停，但可以降低随机数据恰好触发危险系统操作的概率。

## 6. 遥测布局

### `0x181` 轮速

四个 int16，依次为左目标、左实测、右目标、右实测，单位 mm/s。

### `0x182` PWM

四个 int16，依次为左 PWM、右 PWM、左误差、右误差；误差单位 mm/s。

### `0x183/0x184` 编码器

字节 0..3 为 int32 累计计数，4..5 为 int16 最近控制周期增量，6 为配对序号，7 为 CRC。左右相同序号才由 ROS 用于一次里程计更新。

### `0x185` 状态

字节 0 状态，1..2 故障位，3..4 电池 mV，5 最近命令序号，6 控制周期异常累计值（饱和到 255），7 CRC。

### `0x186` 应答

字节 0 参数 ID（系统命令用 `0xFE`），1 状态码，2..5 float32 值，6 序号，7 CRC。状态码：0 成功、1 CRC 错、2 未知参数、3 数值非法、4 当前状态拒绝、5 Flash 错误。

### `0x700` 心跳

字节 0..3 运行毫秒数，4 状态，5 固件主版本，6 次版本，7 CRC。

## 7. 使用 `candump` 验证

```bash
candump -tz can0,101:7FF,181:7FF,182:7FF,183:7FF,184:7FF,185:7FF,186:7FF,700:7FF
```

不要手工随意构造 `0x101` 驱动车轮，因为 CRC、enable 和速度单位任何一个写错都可能造成误判。优先用 ROS 节点或项目的协议代码生成。
