# 测试、验收与项目呈现

## 1. 已完成的软件级验证

电脑端 `tests/test_main.c` 覆盖：

- CRC-8/ATM 标准向量；
- 速度命令编解码及单字节破坏拒绝；
- 默认参数、CRC32、合法修改和越界拒绝；
- 前馈 + PI 输出方向、PWM 限幅和安全失能清积分；
- IDLE -> RUNNING -> TIMEOUT -> RUNNING 状态变化；
- 相同左右计数下的直行里程计；
- 急停锁存及按正确顺序清故障。

Windows 上运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run_c_tests.ps1
```

ROS 协议测试在 `ros2_ws/src/chassis_can_control/test/test_can_protocol.py`。RDK 上安装 pytest 后：

```bash
cd ~/chassis_project/ros2_ws/src/chassis_can_control
python3 -m pytest test/test_can_protocol.py -q
```

未安装 pytest 时可直接运行同一组测试函数：

```bash
python3 test/run_protocol_tests.py
```

## 2. 分阶段硬件验收

| 阶段 | 条件 | 操作 | 通过标准 |
|---|---|---|---|
| A 通讯 | EN 关闭 | 启动 CAN 和 ROS 节点 | 1 s 心跳稳定，无 bus-off |
| B 编码器 | 电机失能 | 手转左右轮 | 向前计数为正，圈数标定重复误差小 |
| C PWM 方向 | 车轮离地 | 分别低速正/反转 | 机械方向与编码器速度符号一致 |
| D 闭环 | 车轮离地 | 0.05~0.3 m/s 阶跃 | 不持续振荡，不超过 PWM 上限 |
| E 超时 | 低速运行 | 停止 ROS 节点或断 CAN | 约 200 ms 撤销输出，状态 TIMEOUT |
| F 急停 | 低速运行 | 调用 estop 服务 | 当前周期附近撤销输出，故障锁存 |
| G 堵转 | 受控低速 | 可控阻挡单轮 | 规定时间内 FAULT 并撤销两轮输出 |
| H 直行 | 平整地面 | 多次 5 m 直行 | 记录横向偏差并可通过同步参数改善 |
| I 里程计 | 平整地面 | 固定距离和整圈旋转 | 轮径/轮距修正后误差达到目标 |
| J 长稳 | 正常载荷 | 连续运行 30~60 min | 无栈溢出、bus-off、异常复位和过热 |

## 3. 建议的量化指标

最终数值必须实测，不应预先写死。建议至少给出：

- 0.1 -> 0.3 m/s 阶跃上升时间；
- 稳态速度误差百分比；
- 最大超调百分比；
- 5 m 直行横向偏差；
- 5 m 里程计距离误差；
- 通信断开到 PWM 清零的实测时间；
- 堵转触发时间；
- 30 min CAN 丢帧/错误计数和控制 overrun 数。

## 4. 常见故障排查

### 一使能就满速或振荡

立即断电。检查编码器符号是否与 PWM 正方向一致、每圈计数是否错误、Kp/Ki 是否过大，以及原 `Balance_task` 是否仍在运行。

### 有心跳但 STM32 不响应速度命令

检查 `0x101` 是否标准帧、DLC 8、协议版本 1、CRC 正确；确认原 CAN 中断已关闭，没有提前取走 FIFO；看 `/diagnostics` 是否处于 HARDWARE_DISABLED 或锁存故障。

### 无心跳且 CAN error counter 增长

优先查位速率、终端电阻、H/L、共地和收发器供电。两端 500 kbit/s/1 Mbit/s 不一致是高概率原因。

### 低速不动，高速突然冲

死区或 Kff 不合适。先把车轮离地测最小持续转动 PWM，不要用很大的积分去硬顶静摩擦。

### 里程计距离成固定比例错误

检查 `counts_per_wheel_rev` 和有效轮径。若角度误差而直线距离正确，主要检查轮距。

### 参数保存后重启异常

检查是否与原工程共享 `FLASH_SAVE_ADDR`、结构大小是否超过扇区、写 Flash 返回状态，以及供电是否在擦写时中断。参数 CRC 不通过时固件会使用默认值。

## 5. 简历项目表述建议

项目可以表述为“基于 STM32F407 与 RDK X5 的 ROS 2 移动底盘电机闭环与 CAN 通信系统”。内容应以你真正完成的测试结果为准，例如：

- 在 STM32F407 上设计 100 Hz 双轮速度闭环，实现前馈 + PI、积分抗饱和、速度斜坡、编码器低通滤波和直行同步；
- 设计带 CRC、序号、参数管理和心跳的 CAN 2.0A 协议，打通 RDK X5 SocketCAN 与 ROS 2 `/cmd_vel`、里程计和诊断数据；
- 实现命令超时、急停锁存、欠压、编码器异常和堵转状态机，并通过断链、堵转、长稳测试验证；
- 通过 rosbag 采集目标/实测轮速和 PWM，完成死区、前馈、PI、有效轮径与轮距标定，将实测误差从 X 改善到 Y。

最后一条的 X/Y 必须用自己的实车数据填写。面试时能展示控制框图、协议表、关键波形和故障测试视频，含金量会明显高于只展示“调用电机驱动接口”。
